# fix(launchpad): make cascade produce real outputs (5-phase data fix)

PR #1237 in modernagencysales/mas-platform — closed — by Ajma1 — [https://github.com/modernagencysales/mas-platform/pull/1237](https://github.com/modernagencysales/mas-platform/pull/1237)

## Summary

The cascade infrastructure from #1234 (dispatch helper, watchdog, await-autoTrigger, env secrets) flows end-to-end — but every downstream step produces empty outputs because users who attach a Blueprint prospect without clicking **Connect Blueprint** leave \`intake_data\` empty. Five orthogonal root-cause fixes on the same code path:

| # | Phase | What it fixes |
|---|---|---|
| 1 | **Auto-connect Blueprint** | \`completeOnboarding\` projects the attached prospect into \`intake_data\` if status=complete; warns (without blocking) if still enriching |
| 2 | **Hydrate-intake fallback** | \`hydrateLaunchPadIntake(intake, fallbackProspect?)\` derives \`clientCompany\`/\`clientIndustry\` from \`raw_profile_json.company\` (or email-domain root) — stops every Trigger task downstream from Zod-rejecting on \`clientCompany: null\` |
| 3 | **Surface AI error** | \`knowledge_base\` handler pushes the actual Anthropic failure (status/code/name/message) into the step row's \`gaps[]\` array + adds model+token-budget context to the log |
| 4 | **Copilot replay guard** | Scope to \`max(pendingToolCall.created_at, last user message)\` so a fresh user turn that re-references the same \`tool_call_id\` no longer trips \`already_executed\` |
| 5 | **Build-lead-list tenant resolution** | Resolve account through \`accounts_memberships\` (owner role) so the \`team_id\` used in MCP envelopes is guaranteed to be in \`accessibleTeamIds\` — removes the basejump personal-account silent miss that produced \`PROVIDER_REQUEST_FAILED: Access denied to team <user_id>\` |
