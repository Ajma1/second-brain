# fix(copilot): unblock /w/me/copilot/new by dropping legacy team_id FKs

PR #1251 in modernagencysales/mas-platform — closed — by Ajma1 — [https://github.com/modernagencysales/mas-platform/pull/1251](https://github.com/modernagencysales/mas-platform/pull/1251)

## Summary

Hotfix. `/w/me/copilot/new` raised `violates foreign key constraint "copilot_conversations_team_id_fkey"` for every user in their personal workspace, blocking any new copilot conversation (which means PR #1247 and PR #1249's lead-magnet fixes can't be exercised from `/w/me/*` either).

**Root cause** — \`resolveScopeFromSlug('me', userId)\` (packages/db/src/resolve.ts:80–92) returns \`{ type: 'team', teamId: <identity.workspaces.id>, … }\`, projecting the workspace UUID onto \`scope.teamId\`. The four copilot tables still carry a FK on \`team_id\` pointing at \`public.teams(id)\`. For non-personal workspaces this mostly worked because \`teams.id == workspaces.id\` by historical mirror, but a personal workspace only exists in \`identity.workspaces\` (no \`public.teams\` row), so every personal-scope insert failed.

Migration drops the FK on:
- \`copilot_conversations_team_id_fkey\`
- \`copilot_messages_team_id_fkey\`
- \`copilot_memories_team_id_fkey\`
- \`copilot_conversation_folders_team_id_fkey\`

\`applyScope\` already treats \`team_id\` as a workspace UUID; \`workspace_id\` on the same tables keeps its FK to \`identity.workspaces(id)\` as the source of truth.

## Test plan
- [x] Audit: \`select count(*) from public.copilot_conversations where team_id is not null and not exists (select 1 from teams where t.id = team_id)\` = 0 → no orphan rows today; the FK was strictly the insert gate.
- [ ] Post-deploy: visit \`/w/me/copilot/new\`, send a message → conversation streams successfully (pre-fix: instant 500 with FK violation).
- [ ] Sanity: existing team-workspace conversation flow unaffected — \`team_id\` column still populated with the workspace UUID; \`applyScope\` continues to filter by it.

## Follow-up (separate PR)
Rename \`team_id\` → \`workspace_id\` (or drop \`team_id\` entirely) once every read site uses \`workspace_id\`. Tracked alongside the broader workspace_id migration in #1245 / Tranche D.
