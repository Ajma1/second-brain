# fix(copilot): unwrap confirm-action API envelope so tool result shows 'Done'

PR #1241 in modernagencysales/mas-platform — closed — by Ajma1 — [https://github.com/modernagencysales/mas-platform/pull/1241](https://github.com/modernagencysales/mas-platform/pull/1241)

## Summary

Two bugs combined to render every confirmed copilot tool call as **Failed**, even when the action returned \`success: true\`. Screenshot context: live user clicked Confirm on \`begin_lead_magnet_creation\` — the JSON dump showed \`{ executed: true, result: { success: true, ... } }\` and the badge said "Failed".

### Bug 1 — optimistic state stored the API envelope, not the ActionResult

\`useConversationStream.confirmAction\` (\`apps/app/src/components/copilot/useConversationStream.ts:707\`) stored the raw fetch response \`{ executed, result }\` as \`toolResult\`. Every downstream consumer reads \`success\` / \`error\` off the inner ActionResult shape, so \`toolResult.success\` was always \`undefined\` → falsy.

### Bug 2 — label was \`!success\` instead of \`failed\`

\`MessageList\` (\`apps/app/src/components/copilot/MessageList.tsx:340\`) computed a \`failed\` predicate but never used it. The label fell through \`pending ? 'Pending' : success ? 'Done' : 'Failed'\` — so any tool result missing a top-level \`success\` (Bug 1, or any plain-data response) rendered as **Failed**.

## Fix

- Unwrap the envelope on the optimistic insert path: \`toolResult = result.result ?? result\`
- Drive label off \`failed\` (the predicate that was already correct)
- Drop the unused \`success\` local

The persisted DB row was always the right ActionResult shape; this only fixes the local optimistic state path.
