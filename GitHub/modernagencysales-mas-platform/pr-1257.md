# fix(db): repair provision_user_team schema drift (silent signup failures)

PR #1257 in modernagencysales/mas-platform — open — by kimprobably — [https://github.com/modernagencysales/mas-platform/pull/1257](https://github.com/modernagencysales/mas-platform/pull/1257)

## Incident

`provision_user_team()` had drifted from the multi-tenancy schema and threw on **every new signup since ~2026-05-06**. The `handle_new_user` trigger catches the error and logs it to `signup_errors`, so the failure was silent: a new user ended up with an `auth.users` row but **no `public.users`, team, subscription, or `team_profile`** — a hollow account that can log in but does nothing.

Surfaced when a new DFY client (`bernard@ppcmaestro.com`) couldn't be onboarded — the `/api/v2/ops/admin/dfy/onboard` endpoint 500'd because `createAccount` hit the same broken trigger.

## Root cause — three drift bugs

| # | Insert | Bug |
|---|--------|-----|
| 1 | `team_members` (x2) | omitted `workspace_id` (NOT NULL) |
| 2 | `subscriptions` | referenced a `team_id` column that no longer exists |
| 3 | `team_profiles` (x2) | omitted `workspace_id` (NOT NULL) |

`workspace_id == team_id` per the Phase 6a 1:1 model (`accounts.id == teams.id == workspaces.id`) — verified true for all 460 existing `team_members` rows.

## Fix

`CREATE OR REPLACE FUNCTION public.provision_user_team` with all three inserts corrected. Body otherwise unchanged. Idempotent — safe to re-apply.

## Already applied to production

Signups were actively failing, so this was applied as a hotfix ahead of this PR (per agreed emergency path). This PR makes the repo match prod; CI re-applying the idempotent `CREATE OR REPLACE` on merge is a no-op.

**Backfill:** 8 affected users (6 fully orphaned, 2 partial) were repaired by re-running the now-fixed, idempotent function. All 8 verified at `1/1/1/1` for `public.users` / `team_members` / `subscriptions` / `team_profiles`; zero orphaned `auth.users` remain.

## Verification

- Production function replaced; `[]` (DDL ok)
- Backfill returned a `team_id` for all 8 users
- Post-backfill row-count check: all 8 complete, 0 orphans
- `bernard@ppcmaestro.com` onboarded: `launch_pad_state` (`dfy_managed`), 12 step rows, agency `account_link` created

## Follow-ups (not in this PR)

- `team_members.account_id` is nullable and the function never sets it (pre-existing; 26 of 460 rows are null). Left as-is to keep scope minimal — worth a separate look.
- An earlier `legacy_account_map` variant of this drift (signup_errors, May 3–5) appears already fixed; not re-investigated here.
