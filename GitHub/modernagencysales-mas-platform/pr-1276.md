# fix(gtm-os): match AI-tool route under workspace prefix in LMS

PR #1276 in modernagencysales/mas-platform — closed — by kimprobably — [https://github.com/modernagencysales/mas-platform/pull/1276](https://github.com/modernagencysales/mas-platform/pull/1276)

## Problem

Bootcamp students report every AI tool in `modernagencysales.com/learn` "takes me back to Week 1." Clicking an AI tool (e.g. Niche Finder, Profile Optimizer) changes the URL to `/w/<workspace>/learn/ai-tools/<slug>` but the page renders **Week 1: PST Recording** instead of the tool.

## Root cause

`BootcampLayout.tsx` matched the AI-tool route with a pre-migration pattern:

```js
const aiToolMatch = useMatch('/learn/ai-tools/:slug');   // ❌ no workspace prefix
```

`useMatch` matches against the **absolute** pathname. The Learn tree moved under `/w/:slug/learn/*` in migration `hq-l0lz.13`, so the real URL is `/w/hellos-workspace/learn/ai-tools/niche-finder`. The prefix-less pattern never matches → `aiToolMatch` is `null` → the component falls through to `VirtualLessonRouter`, which renders `currentLesson` (defaulting to the first lesson, Week 1).

> Tell-tale: a missing-from-DB tool would still match and show `ChatInterface`'s "AI Tool Not Found" error. It showed a *lesson* instead — so the match itself was failing, not the data.

## Fix

1. **Match pattern now includes the workspace prefix** — extracted to an exported, tested `AI_TOOL_ROUTE = '/w/:workspaceSlug/learn/ai-tools/:slug'`.
2. **Closed a sibling bug**: lessons navigate via React state (`setCurrentLesson`, no URL change) while tools navigate via `href` (URL change). Once the match works, selecting a lesson while on a tool URL would leave `ChatInterface` mounted over the lesson. Lesson selection now clears an active tool URL; all lesson entry points (sidebar, breadcrumb, prev/next, command palette) route through one memoized `handleSelectLesson`.
3. **Regression test** asserting the new pattern matches the workspace URL and the old prefix-less one does not.
