### What changed
- **Resolve-once / read-by-ref.** Workflow args shrink to `{ ownerId, topic, bucketId?, methodologyKey? }`. A new `resolveContext` step loads methodology + profile + accepted grounded nodes from the DB and derives overlay / voiceBrief / template **once**, storing a compact `resolvedContext` on the run row. Every step reads it via `getResolvedContext`, so **journaled step args are tiny** (`{ workflowId, … }`) instead of threading the full methodology doc through 4+ steps.
- **Full typing.** No stray `v.any()` (only the methodology `doc` — stored `v.any()` in its own table — and `onComplete`'s library-typed `context`). `getPostRun` is a typed projection. `hookStep` returns `winnerScore` so the handler never re-finds it by archetype.
- **`pickBest` generalized** to `<T extends { score: number }>` and used by the handler as the single keep-best source; `iterations` counts applied revisions only.
- **Lifecycle hardening.** `initRun` is idempotent by `workflowId` (retry-safe); `resolvedContext` cleared on both terminal paths (`finishRun` + `onComplete` failure).
- **New `docs/superpowers/golden-convex-workflow.md`** — the reusable patterns + gotchas (handler purity, resolve-once, serializable returns, `step.workflowId`, lifecycle/`onComplete`, bounded keep-best, the same-file `runQuery` TS7022 inference cycle, persistent-`convex dev`-for-async).
