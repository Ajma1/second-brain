# Brain — surface the computed synthesis layer (positions/opportunities/gaps)

PR #29 in modernagencysales/maestro-agent-planning — closed — by kimprobably — [https://github.com/modernagencysales/maestro-agent-planning/pull/29](https://github.com/modernagencysales/maestro-agent-planning/pull/29)

## Summary
You were right — the brain page was regurgitating raw facts and ignoring the real synthesis stack the product computes. This surfaces it, and computes it for new users during onboarding.

## The synthesis stack (what existed but went unshown)
\`\`\`
facts → topic clusters → POSITIONS (beliefs) → OPPORTUNITIES (what to make) → GAPS (what's missing)
                                              ↘ all gated by QUALITY RULES + GATE RUNS
\`\`\`

## Brain page rebuilt as a synthesis narrative
- **Positions** (headline — \"what your brain believes\"): stance + thesis + confidence + readiness. Each card **expands to reveal its supporting facts** (real \`supportNodeIds\` → fact cards with source pills) plus tensions. That conclusion→evidence drill-down is what makes it read as *computation*, not a list. Also shows linked opportunity count.
- **Opportunities** (\"what to make next\"): grounded in a position, readiness + priority + recommended action + support quote + missing slots.
- **Gaps** (\"what Sandra needs from you\"): type + owner role.
- **Quality system** (collapsible): rules + latest failed gate.
- **All facts** (collapsible): the evidence foundation — demoted from headline to footnote.

## Onboarding now computes synthesis for new users
Previously onboarding made facts but left the synthesis layer empty for new users. Added \`runHigherOrderSynthesis\`: one Haiku call turns the 4 facts into 2 positions + 2 opportunities + 1 gap, referencing facts by index → mapped to real \`groundedNode\` ids so the drill-down actually works. New \`insertPosition\`/\`insertOpportunity\`/\`insertGap\` mutations.

## E2E proof (Raphael + admanage.ai)
Real computed positions:
- **\"Speed is the competitive moat in ad ops\"** — operating_principle, 85%, *strong*. Tension: \"faster launches could incentivize lower-quality creative.\" Gap: \"no data on ROAS impact vs. speed gains.\"
- **\"Bootstrapped founders build differently than VC\"** — belief, 78%, *usable*.

Both wired to real supporting facts → the expand drill-down shows the evidence.

## Honest limitations
- **Data accumulation** — onboarding runs append to the dev user, so their brain now mixes Raphael's positions with the seeded Maestro ones. Prototype reality; a reset mutation is a quick add if it bothers.
- **Citations/usage still mostly 0** — opportunities' \`supportQuotes\` come from seed citations; onboarding-computed opportunities reference nodes but those nodes have no citation rows yet, so quotes may be empty on new ones.
- **No deliberate graph viz** — still cards, not a radial graph, on purpose.
