# feat(funnels): component palette architecture (Phase 1)

## Summary

Phase 1 of the component palette architecture (spec PR #14, plan PR `plan-palette-build`). Replaces the 13-hand-built-Native-component renderer with a curated palette of 38 shadcn pro blocks + smart LLM picker.

**Live verification (just now)**: a fresh funnel built with prompt "build for technical founders" produced 13/13 sections rendered via palette picks. Audience inference correctly returned "notion-doc" and biased the picks toward MinimalHero / FounderNoteHero / NumberedAlternatingRows / GatedDocumentCapture — all stylistically appropriate for the inferred audience.

## What's in this PR (1.5 days, 16 commits)

**Schema + seed**
- `brandProfiles` table + per-customer brand tokens (colors, fonts, density, voice)
- `funnels.brandProfileId` auto-linked + `funnels.audienceStyle` field
- Maestro Default brand profile seeded; `createFunnel` auto-links it

**Palette infrastructure**
- `src/lib/funnels/palette/{types,registry,render,shortlist}.{ts,tsx}` — contract + dispatch + deterministic shortlist
- `convex/lib/{paletteSpecs,renderers/palette}.ts` — server-side mirror for the LLM picker
- `src/lib/funnels/brand/theme.ts` — brand-tokens → CSS vars
- Studio applies brand CSS vars at the root

**Classifier + dispatch**
- Classifier extended to emit `audienceStyle` (no extra LLM hop; folded into existing call)
- New per-section LLM picker validates shortlist + zod-typed props with 1-shot retry
- Graceful native fallback for any slot without palette coverage (none in v1)

## Known limitations / Phase 2 items

1. **`MultiStepQuiz` (the Tally clone)** still uses the single-step `AffinityQuizBlock` placeholder. Hand-build is spec'd but deferred to Phase 1.5.
2. **`SeverityInsightCards` + `InlineVSLWithTranscript`** hand-builds also deferred.
3. **`form-multi-step` field structure is hardcoded** (only step titles are prop-driven). Deferred.
4. **One-shot migration mutation** for legacy funnels not yet wired (legacy funnels still render fine via fallback path).
5. **Deep dive section can hit max_tokens** for very long outputs (one earlier smoke had a JSON parse error). Per-section max_tokens budgets like we did for C1 would fix.
