# Methodology Platform — Ghostwriter Builder (spike)

PR #42 in modernagencysales/maestro-agent-planning — open — by kimprobably — [https://github.com/modernagencysales/maestro-agent-planning/pull/42](https://github.com/modernagencysales/maestro-agent-planning/pull/42)

## What this is

A throwaway spike (in `prototypes/methodology-spike/`) proving the **methodology platform** thesis: a ghostwriter encodes their content method once — mix, cadence, derived templates, rules, voice — and it is **deterministically applied** across all their clients, each in their own **protected voice**, with a **convergence loop** that learns from edits + performance, and an honest **A/B proof**.

Brainstormed → spec'd → planned → built test-first, overnight.

- **Spec:** `docs/superpowers/specs/2026-06-04-methodology-platform-ghostwriter-builder-design.md`
- **Plan:** `docs/superpowers/plans/2026-06-05-methodology-platform-ghostwriter-builder.md`

## The model we converged on

- **Wedge:** ghostwriter-serves-their-clients (not a guru marketplace — that's the fast-follow). Value = reliable delegation → *save time / make more money / scale your method / serve more clients*. Determinism is the mechanism, not the pitch.
- **A methodology = the CMO's policy:** action space (templates) + allocation (mix) + schedule (cadence) + guardrails (rules) + style (voice). The agent chooses *within* enforced rails.
- **Representation:** typed **Spine** (mix, cadence, deterministic rules, protected-dim keys — code-enforced, versioned) + open **Body** (positioning, templates, ai_judge/soft rules, shareable voice — AI-read, grows without migration).
- **Two-level:** shared **Methodology** ∘ per-**Client overlay**. Beliefs/stories/credentials/signature-phrases stay the client's own — never overwritten.
- **Templates are derived:** a great reference post (full copy) → abstracted into structure + slots + an extraction interview. That interview is the taste-transfer mechanism.
- **Convergence:** edits AND performance → one classifier → **method / client / noise** → versioned opt-in updates. Drive edit-rate→0, with performance judged **per-bucket** (a single global engagement number would fight the mix — reward Growth, punish Conversion).

## What's built (TDD, 41 tests green)

`core/`: methodology + overlay types, validation, an LLM seam (OpenRouter, dependency-injected), the Distinctiva 4-bucket seed (3 real templates with embedded post copy), the **template abstractor** (riskiest bet, front-loaded), the compiler (measures mix from real posts), the planner (largest-remainder allocation + cadence + sequence-rule assignment), CMO template select, the voice brief (protected dims), generation (template interview-fill), enforcement (deterministic + ai_judge + group-level), the 3-way evidence classifier (safe-default-to-client), convergence (edit-rate + per-bucket perf + routed apply), the **A/B proof**, and a shared `sequenceRules` module. A thin React `visual/` (Builder / Apply / A·B) renders deterministic fixtures.

## Proven vs. deferred (honest)

- ✅ **Proven** (green gate — 41 tests, typecheck, build): the wiring, the deterministic enforcement, the **protected-voice guarantee** (structural — the methodology has no field that *can* overwrite a client's protected dims; verified a client's signature phrase survives both methodologies unchanged), and **divergence** — the A/B is honest: forcing identical mock output drops `diverged` to `false`, so divergence comes from the methodology objects, not canned strings. ZFC-clean: every *semantic* decision is an LLM call; only *mechanical* checks are regex.
- ⏳ **Deferred to a live key:** real **transfer quality**. `npm run validate:abstractor` and `npm run validate:ab` run the abstractor and the A/B against the real posts via OpenRouter — set `OPENROUTER_API_KEY` and eyeball whether the output is genuinely on-method. **That human judgment is the real test;** the mock proves the machine, not the taste.

## Review + fixes

A final whole-implementation review (opus) came back **green, no Critical findings**. Its two Important findings are fixed in this branch: the group-level adjacency check now reads the methodology's **declared** `no_adjacent` rules (shared `sequenceRules` module) instead of hardcoding `"conversion"`; the convergence "method" route is now **idempotent** (no unbounded soft-rule accretion). Plus a `bumpMinor` NaN guard. Two tests added.

**Carried-forward backlog** (not blockers — for the harvest-into-product step):
- The safe-default fallbacks (abstractor / ai_judge / classify) should **log loudly** when ported, so a systematically broken model response isn't swallowed.
- `select` rotation is thin (avoids only the most-recent template id; doesn't yet weight by remaining mix budget).
- `editRateTrend`'s "converging" verdict should incorporate the **per-bucket performance guard** (the honesty floor against rubber-stamping) — the data is computed (`perBucketPerformance`) but not yet wired to the visual verdict.
- `compile` punts cadence/voice/positioning extraction to the tune step (matches scope; worth making explicit).

## Out of scope (deferred by design)

Marketplace UI + consumer opt-in, propagation/versioning UI, lead-magnet/email extensions, the carousel/visual layer, and the multi-profile-org audience.
