# Time-per-post efficiency metric — track and report content creation speed

- **Identifier:** MAE-357
- **Status:** Backlog
- **Assignee:** —
- **Team:** MAE
- **Updated:** 2026-06-20
- **URL:** https://linear.app/modern-agency-sales/issue/MAE-357/time-per-post-efficiency-metric-track-and-report-content-creation

## User Story

**As a LinkedIn ghostwriter, I want to see how long it takes me to create each post (from source material to client-ready draft), so that I can measure my efficiency gains from using Maestro and justify the tool's value.**

## Source

Dalton Danks call (2026-06-18). Dalton's core bottleneck is time — 20-30 min per post is unsustainable for growth. Reducing this is the #1 value proposition.

> "I perceive my main bottleneck to be that I'm spending too much time in fulfillment like I mentioned like up to 30 minutes a post is really not sustainable to grow further"

## Gap from Existing Issues

No existing issue captures time-per-post as a measurable metric. Multiple issues contribute to speed (batch generation, lint gates, review lifecycle) but none track the outcome.

## Prior Art

**maestro-v2-3**:

* Posts have `createdAt`, `updatedAt`, `scheduledFor`, `publishedAt` — no `creationStartedAt` or `timeToCreate`
* `agentRuns.durationMs` tracks agent compute time, not user effort

**mas-platform**:

* DFY content queue spec explicitly deferred "Analytics on editing speed/throughput per operator" as out of scope
* `edited_at` timestamp exists — `edited_at - created_at` could approximate editing wall-clock
* GTM velocity service (`velocity.service.ts`) measures per-stage duration breakdowns — architectural template for this feature

## Implementation Notes

Track key timestamps: draft_generated_at, first_edit_at, last_edit_at, submitted_for_review_at, approved_at. Compute active editing time (last_edit - first_edit) and total cycle time (approved - draft_generated). Surface per-client averages and trend lines. This is a powerful retention/sales metric: "You used to spend 25 min/post, now it's 8 min."
