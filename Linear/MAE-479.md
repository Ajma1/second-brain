## Outcome

Provision the dedicated staging identity/workspace/evidence fixture required for authenticated /inspiration desktop/mobile light/dark acceptance without using customer data or crossing tenants.

## Verified read-only diagnosis

* The BWS smoke credentials are accepted by staging AuthKit.
* Current email/password locators and submits work.
* No MFA, email code, CAPTCHA, bad-password state, callback loop, or unauthenticated gate occurred.
* The callback returned to Maestro, although the requested /inspiration return path was not preserved.
* The staging WorkOS project has zero organization memberships for the smoke identity.
* Staging Convex contains the matching WorkOS subject, but its stored email projection does not match the smoke credential and it has zero active workspace memberships.
* Therefore this identity has zero accessible Inspiration workspaces, personas, serving pointers, bundles, or recommendations.
* The existing active production-harvest release in staging is outside this identity's membership. It must not be reused for acceptance.
* The deployed staging AuthKit client does not match the default BWS client mapping, and WORKOS_CLIENT_ID_STAGING is absent.

Do not include emails, user/org/workspace/persona IDs, client IDs, secrets, cookies, callback state, or raw logs in this issue.

## Required owner actions

1. WorkOS owner attests the deployed staging client and API-project mapping and stores the approved presence-only staging client mapping in BWS.
2. WorkOS/Convex identity owner repairs or resynchronizes the smoke user's staging identity projection.
3. Maestro seed owner creates a named disposable staging QA organization/workspace with recorded owner, created timestamp, and reset policy.
4. Grant the smoke identity editor-or-stronger access only to that disposable workspace, except for a separately approved multi-workspace negative test.
5. Tenant-safely seed and activate an approved real Inspiration persona/bundle/evidence set inside that workspace. Do not copy or attach the existing other-tenant release.
6. Record only safe provenance metadata needed by the acceptance run.

## Acceptance

* Authenticated login returns to /inspiration or client navigation reaches it without an auth loop.
* The disposable workspace/persona provenance is owner-attested and resettable.
* The smoke identity can read the approved real Inspiration bundle only inside its own workspace.
* A tenant-negative assertion proves it cannot read another workspace's bundle.
* No fixture/demo/offline data, invented metrics, customer account, or cross-tenant attachment is used.
* The final exact-SHA desktop/mobile light/dark matrix remains read-only and is run only after the code cutover is deployed.
