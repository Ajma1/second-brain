# Product Brain OKF export from canonical Brain v1

- **Identifier:** MAE-392
- **Status:** In Progress
- **Assignee:** Tim Keen
- **Team:** MAE
- **Updated:** 2026-06-22
- **URL:** https://linear.app/modern-agency-sales/issue/MAE-392/product-brain-okf-export-from-canonical-brain-v1

## User Story

As a Maestro operator, I want OKF export to project from canonical Brain v1 rows, so OKF stays as the portability artifact without keeping a second claim/position store alive.

## Context

Current `brain.export_` serializes the legacy concept registry. That remains compatible for current callers, but new Brain truth lives in Convex `sources`, `claims`, `claimCitations`, `knowledgeFiles`, and Brain-specific version ledgers. Product direction is to retain OKF while removing ambiguity about storage ownership.

## Scope

* Design and implement an OKF projection over canonical Brain v1 current rows and version ledgers.
* Preserve existing `brain.export_` compatibility during migration.
* Ensure exported claims include citation/source references from `claimCitations` and `sources`.
* Treat positions as a derived slice; do not make `conceptVersions` the source of canonical positions.
* Add deterministic export tests for byte stability, workspace/client scoping, and citation preservation.

## Acceptance

* OKF export can be produced from canonical Brain v1 data.
* Existing concept-registry OKF callers have an explicit compatibility path or transition path.
* No new cited claim truth is written to `conceptVersions`.
* The export docs explain that OKF is portability, not canonical storage.
