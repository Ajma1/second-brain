## Goal

Add narrow Harvest adapter functions for engagement endpoints so all engagement sampling uses the existing Convex adapter boundary.

## Files

Modify:

* `packages/convex/convex/adapters/harvest.ts`
* `packages/convex/convex/adapters/harvest.test.ts`

## Work

Add and test gateway functions:

* `harvestPostComments({ postUrl, cursor?, page? })`
* `harvestPostReactions({ postUrl, cursor?, page? })`
* `harvestProfileComments({ profileId, postedLimit?, cursor?, page? })`
* `harvestProfileReactions({ profileId, postedLimit?, cursor?, page? })`

Each function should call the correct `/linkedin/...` endpoint through the existing Harvest GET helper, set `paginationToken` and `page` params when provided, and parse the raw response with `harvestEngagementParser.ts`.

## Constraints

* Do not add Harvest calls directly to analytics tooling.
* Keep auth/path/query behavior covered by adapter tests.
* Engagement sampling remains sparse and outside the creator enrichment loop.

Expected: PASS.
