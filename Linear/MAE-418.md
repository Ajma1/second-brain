## Goal

Create the engagement sampler runner that can plan and dry-run Harvest engagement sampling safely before live calls are enabled.

## Files

Create:

* `tooling/corpus/beneficial-adjacency/engagement-sampler.mts`

Modify:

* `tooling/corpus/linkedin-beneficial-adjacency.mts`
* `tooling/corpus/linkedin-beneficial-adjacency.test.mts`

## Work

Implement a comments-first sampler skeleton that:

* Reads `engagement_sample_plan.csv`.
* Computes expected Harvest requests before live execution.
* Supports dry-run mode that writes planned calls and budget ledger with zero provider calls.
* Uses only `packages/convex/convex/adapters/harvest.ts` gateway functions for live mode.
* Writes `post_commenters.jsonl` and optionally `post_reactors.jsonl` with canonical actor keys and redacted default fields.
* Records stage state for resumability and skipped/failed rows.

## Constraints

* Default scope should be sparse: one or a few high-value posts per creator, not every post.
* Do not print or persist Harvest API secrets.
* Actor-level engagement remains analytics-only by default.

## Verification

Run:

```bash
rtk env HOST_TEST_MAX_LOAD_1M=100 host-test-slot --class focused pnpm exec tsx --test tooling/corpus/linkedin-beneficial-adjacency.test.mts
```

Expected: PASS.

## Acceptance Criteria

* Dry-run tests prove zero Harvest calls.
* Live path is injectable/mocked and calls only the adapter gateway.
* Output rows include canonical actor keys, source post evidence, and privacy-safe defaults.
