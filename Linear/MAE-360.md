# Call capture → product discovery pipeline — auto-extract user stories and route to backlog

- **Identifier:** MAE-360
- **Status:** In Progress
- **Assignee:** Tim Keen
- **Team:** MAE
- **Updated:** 2026-06-23
- **URL:** https://linear.app/modern-agency-sales/issue/MAE-360/call-capture-product-discovery-pipeline-auto-extract-user-stories-and

## User Story

**As a product owner, I want prospect and customer call transcripts automatically processed into user stories and matched against the existing backlog, so that customer discovery insights flow into the roadmap without manual extraction.**

## Source

Dalton Danks call workflow (2026-06-18). The process of extracting user stories from a single prospect call, matching against ~300 existing Linear issues, researching prior art across 3 repos, and creating 10 issues took ~30 minutes with heavy AI assistance. This should be automated end-to-end.

## Capability

When a call recording lands in Maestro (via maestro-capture):

1. Transcript is processed into the brain with full provenance
2. An agent extracts user stories — pain points, desires, workflow gaps — attributed to the speaker
3. Stories are matched against the existing Linear backlog (MATCH / PARTIAL / NEW)
4. NEW stories are created as Linear issues with source quotes, call attribution, and priority signals
5. PARTIAL matches enrich existing issues with additional prospect evidence
6. Cross-call patterns are surfaced ("5/8 prospects mentioned fact-checking")

## Integration Points

* maestro-capture → Maestro brain (transcript ingestion)
* Maestro brain → Linear API (issue creation/enrichment)
* Cross-call analytics (pattern detection across all prospect calls)

## Implementation Notes

The extraction → match → create flow has been validated manually in the Dalton Danks call session. The matching step requires semantic comparison against existing issue titles and descriptions, not just keyword search. Prior art research across repos is a stretch goal — the core loop is extract → match → create/enrich.
