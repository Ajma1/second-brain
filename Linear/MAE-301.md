Tim 2026-06-12: intent.ts is "sneaking past ZFC by using an AI to do regex." Root cause = our ZFC definition was too shallow ("model not regex"), codified in the v2-3 audit (which cited Haiku-classification as the "counter-example done right") and faithfully reproduced by the overnight build (PR #4).

## The sharpened principle

**If the model's output is a value that code then routes/switches on, you've used AI to make a framework decision — still framework cognition.** True ZFC: the model's output IS the action (a tool call), not a label feeding a switch. An agent INTERPRETS and ACTS via tools; it does not classify natural language into a frozen enum.

* The tell (shape-level, lint-invisible): NL input → model → fixed enum → code switches. Same shape as the v2-3 regex router, regardless of regex vs model.
* When a classifier IS ok: cheap high-volume STRUCTURAL routing with a genuinely fixed action set, labeling/analytics (not driving behavior), or scope guardrails. NOT "understand a user instruction and act."
