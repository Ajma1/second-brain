# P0: CLI OAuth discovery endpoints return 404

- **Identifier:** MAE-507
- **Status:** Backlog
- **Assignee:** —
- **Team:** MAE
- **Updated:** 2026-08-01
- **URL:** https://linear.app/modern-agency-sales/issue/MAE-507/p0-cli-oauth-discovery-endpoints-return-404

## Environment and SHA

* Released CLI: `@maestrogtm/maestro-cli@0.3.0`
* Released tag commit: `61c8ed2a734693bde06829e263f8a47eea79996b`
* Repo-local comparison: `0.3.1` at source `95c9a04c048dcf8806bd754ccc606225b4314e5b`
* Host: clean temporary npm environment on `maestro-worker`, Node 22
* Target: staging only for login; production endpoint was checked read-only for parity

## Minimal reproduction

```sh
npm install @maestrogtm/maestro-cli@0.3.0
maestro login --staging
curl -i https://staging.maestrogtm.com/.well-known/oauth-protected-resource
```

## Expected

`maestro login --staging` discovers OAuth metadata and begins browser or device authorization. The well-known endpoint returns an RFC-compatible JSON resource document.

## Actual

* `maestro login --staging` exits 1 with `Unexpected token 'N', "No matchin"... is not valid JSON`.
* The staging well-known endpoint returns HTTP 404, `content-type: text/plain`, body `No matching routes found`.
* The production well-known endpoint also returns HTTP 404 rather than OAuth metadata.
* No credentials or tokens were printed.

## Suspected boundary

OAuth discovery route deployment/endpoint configuration, plus CLI error handling for non-JSON discovery responses. This does not establish which component owns the missing route.

## Severity and launch impact

**P0 / launch blocker for authenticated CLI.** Login cannot begin, so the released CLI cannot make authenticated Brain calls through the supported OAuth path.
