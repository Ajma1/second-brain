## Goal

Add the embedding execution mode to the beneficial adjacency CLI with cache-first behavior and budget enforcement.

## Files

Modify:

* `tooling/corpus/linkedin-beneficial-adjacency.mts`
* `tooling/corpus/linkedin-beneficial-adjacency.test.mts`
* `package.json` if a separate script is useful

## Work

Add CLI support for an `embed` stage/mode that:

* Reads embedding inputs from local corpus/template/creator artifacts.
* Selects and dedupes inputs using `embedding-cache.mts`.
* Loads existing `embedding_cache.jsonl` when present.
* Estimates expected requests/tokens/USD before any provider call.
* Writes `embedding_inputs.jsonl`, updated `embedding_cache.jsonl`, budget ledger, stage state, and lineage updates.
* Supports a dry-run/plan path that makes zero provider calls.

## Constraints

* Cache hits should not call the provider.
* Over-budget runs must fail closed before provider calls and record abort reason.
* Provider API key must come from environment/config and must not be printed, logged, or committed.

## Verification

Run:

```bash
rtk env HOST_TEST_MAX_LOAD_1M=100 host-test-slot --class focused pnpm exec tsx --test tooling/corpus/linkedin-beneficial-adjacency.test.mts
```

Expected: PASS.

## Acceptance Criteria

* Tests prove dry-run and over-budget modes make zero provider calls.
* Cache-hit behavior avoids provider calls.
* Successful mocked provider call writes cache rows with model and content hash lineage.
