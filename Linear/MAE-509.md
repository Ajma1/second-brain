# P1: installed CLI cannot run mcp manifest

- **Identifier:** MAE-509
- **Status:** Backlog
- **Assignee:** —
- **Team:** MAE
- **Updated:** 2026-08-01
- **URL:** https://linear.app/modern-agency-sales/issue/MAE-509/p1-installed-cli-cannot-run-mcp-manifest

## Environment and SHA

* Released CLI: `@maestrogtm/maestro-cli@0.3.0`, tag commit `61c8ed2a734693bde06829e263f8a47eea79996b`
* Repo-local installable CLI: `0.3.1`, source `95c9a04c048dcf8806bd754ccc606225b4314e5b`
* Repo workflow CLI: same source SHA
* Host: `maestro-worker`, Node 22

## Minimal reproduction

```sh
npm install @maestrogtm/maestro-cli@0.3.0
maestro mcp manifest

# From the repository at the tested SHA
pnpm --silent maestro mcp manifest
```

## Expected

The installed `maestro mcp manifest` command returns the same deterministic MCP manifest available through the repo workflow CLI, or installed help/docs clearly expose the supported equivalent.

## Actual

* Released `0.3.0`: exit 1, stderr `mcp must be run through mainAsync`.
* Repo-local installable `0.3.1`: same exit 1 and stderr.
* Installed help advertises only `mcp [--help]`.
* Repo workflow CLI succeeds and returns `maestro-mcp-manifest/v1` with `maestro.search`, `maestro.describe`, and `maestro.execute`.
* `maestro operations search brain` and `maestro operations describe brain.concepts.list` exit 2 as expected because those are not installed commands; the supported Brain equivalents are `headless inspect` and `headless schema`.

## Suspected boundary

Installable CLI command dispatch/parity versus the repo workflow CLI, with possible stale user-facing command documentation. No root cause is asserted.

## Severity and launch impact

**P1 for coding-agent/MCP launch.** Agents cannot retrieve the advertised deterministic MCP manifest from the released executable even though the repo-local workflow command supports it.
