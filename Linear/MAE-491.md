# feat: content rule to detect and block SEO keyword stuffing

- **Identifier:** MAE-491
- **Status:** Backlog
- **Assignee:** —
- **Team:** MAE
- **Updated:** 2026-07-30
- **URL:** https://linear.app/modern-agency-sales/issue/MAE-491/feat-content-rule-to-detect-and-block-seo-keyword-stuffing

## User need

When asking AI to optimize for SEO density, the output stops feeling like human writing. Keyword stuffing makes content sound robotic even when the voice was initially matched.

**Aman's words:** "keyword stuffing when asked to optimize for SEO density — output stops feeling like human writing"

## What this solves

Ghostwriters want SEO-aware content but current AI tools over-optimize when given SEO instructions. There's no guardrail between "include relevant keywords" and "stuff keywords until it sounds like a robot."

## Proposed solution

Add a deterministic content rule (`keyword_density` or `seo_stuffing`) that:

* Counts keyword frequency per paragraph
* Flags when any keyword appears more than N times per 100 words
* Blocks the draft if density exceeds a configurable threshold
* Works as a `hard` rule in the lint pipeline

This fits the existing content lint architecture in `checks/contentLint.ts`.

## ICP evidence

* Aman (call 15): keyword stuffing kills human feel
* Adam (call): interested in "humanized AI" content — voice-authentic, no AI slop
* Muhammad (call): edits AI output manually to avoid "AI slop"
