# [ARCH-019] Build Convex content-runtime hardening slice

- **Identifier:** MAE-208
- **Status:** Done
- **Assignee:** —
- **Team:** MAE
- **Updated:** 2026-05-21
- **URL:** https://linear.app/modern-agency-sales/issue/MAE-208/arch-019-build-convex-content-runtime-hardening-slice

## Context

Hatchet may be a better fit than Temporal for Maestro's AI content runtime or for the internal agent/factory runtime. We need a concrete side-by-side test, not a vibes comparison. Use the same content-object workload, the same deterministic gate package shape, and the same success metrics for both runtimes.

Parent decision issue: [MAE-203](https://linear.app/modern-agency-sales/issue/MAE-203/arch-014-evaluate-hatchet-vs-temporal-for-content-runtime-and-factory).

## Scope

Build or spike two minimal implementations of the same workflow:

* Temporal implementation: `ContentObjectWorkflow` with Activities, Query, Signal/Update, deterministic gate Activity, repair Activity, and export guard.
* Hatchet implementation: durable task/workflow equivalent with child tasks, event waits, streaming, deterministic gate child task, repair child task, and export guard.

The workload must exercise:

* start request with tenant/client/object ids
* load fake context bundle
* stream provisional post deltas
* persist object version and stream cursor outside runtime history
* run deterministic gate fixture
* fail once, repair once, re-check
* block export before ready
* wait for human approval/edit event
* crash/restart or evict/resume worker
* inspect runtime history/event log and evidence

## Metrics

Capture the same metrics for both:

* first status event latency
* first provisional token/delta latency
* time to first provisional post
* time to gate-passed ready object
* repair success path clarity
* crash/restart recovery behavior
* event/history size and contents
* stream replay/reconnect approach
* required idempotency code
* static gate burden for agents
* local dev setup time
* self-host/deployment complexity
* observability quality

## Acceptance Criteria

* Both prototypes use the same input fixture and deterministic gate fixture.
* Both produce an evidence report with object id, version id, rule id, runtime run id, worker logs, and history/event-log summary.
* Both prove export/sync/publish cannot occur before the exact version is ready.
* The bakeoff documents where Hatchet is better, where Temporal is better, and where either requires product-side infrastructure.
* Results feed [MAE-203](https://linear.app/modern-agency-sales/issue/MAE-203/arch-014-evaluate-hatchet-vs-temporal-for-content-runtime-and-factory) and update the runtime ADR if the recommendation changes.
