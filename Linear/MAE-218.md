# MAE-218 — Brain v1 — Per-Client Knowledge Layer

## Work Stream: Brain v1

The per-client knowledge layer. Upload source material (transcripts, websites, docs, posts) → extract cited claims → organize into topics → synthesize positions → feed into content generation so every post is grounded in real client context.

**This week's target: Phase 1 (Foundation) ship gate.**

## Setup

1. Create a new Convex project (greenfield — not inside an existing repo)
2. Clone the schema from the spec (§4)
3. Set up OpenRouter API key (`OPENROUTER_API_KEY`) for LLM calls

## Phase 1 Ship Gate (this week)

Ingest a real transcript, extract claims with markdown, `brain.dump({ clientId })` returns readable markdown with cited claims. `brain.search({ query: "pricing" })` returns relevant claims via vector search. All via Convex durable workflows.

Specifically:

 1. Convex schema: `sources`, `sourceChunks`, `claims`, `claimCitations`, `extractionRuns`
 2. Source ingestion (paste text + URL scrape) — durable workflow (`@convex-dev/workflow`)
 3. Chunking with 100-token overlap
 4. Extraction pipeline (Haiku via OpenRouter, delimiter format)
 5. Grounding validation (deterministic substring check)
 6. Claim markdown rendering
 7. Fingerprint dedup (Tier 1 exact)
 8. Async embedding backfill via scheduler
 9. `brain.dump` — full-client retrieval as concatenated markdown
10. `brain.search` — vector search
11. Headless API: `brain.ingest`, `brain.dump`, `brain.search`, `brain.listClaims`, `brain.acceptClaim`

## Key Convex Gotchas (from §12)

* Actions can't access `ctx.db` — all DB via `ctx.runQuery`/`ctx.runMutation`
* No hyphens in module paths — use camelCase
* Extraction MUST use `@convex-dev/workflow` (bare actions have 10min timeout)
* Embeddings computed async via `ctx.scheduler.runAfter(0, ...)` — never inline
* `workspaces` and `clients` tables: stub for now (see §4.1)
* All LLM calls through OpenRouter, not direct provider APIs
