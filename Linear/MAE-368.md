# Product Brain native Convex corpus and versioned store

- **Identifier:** MAE-368
- **Status:** Backlog
- **Assignee:** —
- **Team:** MAE
- **Updated:** 2026-06-22
- **URL:** https://linear.app/modern-agency-sales/issue/MAE-368/product-brain-native-convex-corpus-and-versioned-store

## User Story

As a Maestro operator, I want Product Brain client/company/call/content knowledge stored natively in Convex with append-only version history, so context packs use a source-backed product store instead of the transitional maestro-score markdown bridge.

## Context

The [MAE-264](https://linear.app/modern-agency-sales/issue/MAE-264/e5-3-agent-context-pack-cited-role-scoped-always-current) Product Brain bridge and API surface made `sources`, `sourceChunks`, `claims`, `claimCitations`, `knowledgeFiles`, `extractionRuns`, and `contextPackRuns` available in Convex. The current bridge can pass read-only readiness, but native corpus ownership and version history are still incomplete. The target architecture is Convex as the Product Brain source of record; `maestro-score` remains only a migration/prior-art source until data is imported.

## Acceptance

* Brain v1 current projection rows remain fast read surfaces for context packs.
* Claim and knowledge-file changes append immutable Convex version rows instead of relying only on in-place patches.
* Read APIs expose scoped version history without exposing mutating Product Brain writes to ordinary coding workers.
* The design distinguishes Product Brain cited business/client/call context from Honcho operational fleet memory.
* `maestro-score` is not required as the long-term runtime source once native ingestion/import is populated.

## Out of Scope For First Slice

* Full UI for history browsing.
* Embeddings or semantic search.
* Automatic adapters for every external source.
* Repointing Hermes brain MCP.
* Product Brain mutating writes in the read-only worker bridge.
