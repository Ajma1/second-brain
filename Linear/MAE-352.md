# Smart example selection — match relevant examples to draft type and topic

- **Status:** Done

## User Story

**As a LinkedIn ghostwriter, I want the system to intelligently select which example posts to use as context for a given draft (matching by post type, topic, or format), so that the AI produces more accurate output without being confused by irrelevant examples.**

## Source

Dalton Danks call (2026-06-18). Dalton provides ~36 example posts per client but suspects this is too many and degrades output quality. No system exists to select the right subset for a given draft.

> "I think one of the things that I haven't played around with too much but it's sort of a suspicion of mine is that I've given it too many examples so that it doesn't actually identify what really it should be matching for"

## Gap from Existing Issues

[MAE-312](https://linear.app/modern-agency-sales/issue/MAE-312/acpf-4-client-voice-and-positioning-summary-capabilities) (client voice summary) builds voice profiles. None specifically address selecting the **right subset of example posts** as few-shot examples for a specific draft type/topic.

## Prior Art (reference for concepts, not code to port)

**maestro-v2-3** (designed, not built):

* Schema has `example_post` as `globalBrainCategory` — tagged by format + niche + stance
* `brain/contextAssembler.ts` does topic classification and retrieves claims, voice_dna, positions — but does NOT query example_post entries
* `draftTemplates.ts` has 5 static templates (story, framework, contrarian, carousel, engagement) — onboarding only

**mas-platform** (3 distinct systems, strong prior art):

* **Template Matcher**: `content-pipeline/template-matcher.ts` — pgvector embeddings (text-embedding-3-small), top 10 by cosine similarity (>=0.3), reranked by semantic(0.4) + performance(0.35) + freshness(0.25). Injects structure, not full posts.
* **Exemplar Graduation**: `services/exemplar-graduation.ts` — posts published with minimal edits + quality scores >=4 graduate to `cp_type_exemplars`. 3 injected per generation. Selects by content_type only, not semantic.
* **Mixer**: `services/mixer.service.ts` — exploits, templates, writing styles each carry `example_posts` arrays. Combo performance tracking.

**maestro-agent-planning**:

* Methodology platform spec: templates carry `examples` (full copy) and `abstracted` (skeleton + slots)
* Profile assets design: Examples as first-class asset group with privacy boundaries between clients

## Implementation Notes

The mas-platform template matcher's embedding + rerank approach is the right architecture. Bridge the gap: use embeddings for topical relevance (like template matcher) but inject full post content as few-shot (like exemplar graduation). Cap at 3-5 examples per generation. Consider auto-graduating high-performing posts.
