## The reframe (why this ticket changed)

The old plan split "versioning" from "attribution" into two tickets. That is a **false horizontal cut** — a fingerprint with no outcome to attach to is unfalsifiable; an outcome ledger with no fingerprint is empty. They are **two ends of one pipe** (stamp → join) and share one prerequisite (the run↔published‑piece edge) that sat in neither ticket. The genuinely separable second system is the **measurement platform** (PostHog), which is now MAE‑222. So we slice **vertically**: this ticket is one thin Convex‑only pipe, end to end.

## Goal

Attribute **one pooled** `edit_rate` **number to one** `methodologyHash`, read back in‑app, **labeled directional** (no randomization yet → observational, not causal — that's MAE‑222's job). Built **content‑type‑agnostic from day one** with exactly one consumer (`postWriting`).

## Load‑bearing prerequisite (verified)

The golden `postWriting` workflow dead‑ends at `awaiting_review`; **nothing reads** `finalText`, and the *published* `contentObjects` come from a different path (`posts.generateDraft`) that never creates a run. So the run↔piece edge + path‑unification is the real first task. In the spike this is a **wiring change** (route generation through `postWriting` + a new accept handoff), not a prod migration.

## Scope

* **Generic** `fingerprint` **validator** (ENGINE/METHOD/CONTENT/EXPERIMENT). `experimentId`/`variant` exist but stay **null** until MAE‑222.
* **Composable METHOD hash:** `methodologyHash = combine(sha256(doc.voiceCore), sha256(doc.modules[workflowType]))` via a **tested canonical‑JSON serializer** (not `JSON.stringify`); CI‑test hash stability. The free `version` string is **display‑only**.
* `methodologyVersions` append‑only snapshot registry (dedup‑by‑hash; written at `resolveContext`). Solves no‑history; enables "what changed"; freezes the rules a judge score ran against.
* **Methodology →** `voiceCore` **+ per‑type** `modules` (the cross‑content compounding asset).
* Stamp `fingerprint` on the **run at** `resolveContext` (before `finishRun` wipes `resolvedContext`).
* `contentObjects` **generalized** to a content‑piece registry: `kind`, `sourceRunId` (**the edge**), denormalized `fingerprint`, optional `ref`. Retire `metrics{}` in favor of the ledger.
* **Generic** `outcomes` **ledger** (`{kind, contentPieceId, fingerprint, metricKind, value, observedAt, source}`) — one table, all content types, all metrics. Stamp `methodologyHash` as a top‑level indexed column.
* **Shared** `acceptRun` **handoff** helper: run → register piece (`sourceRunId`, `fingerprint`) → capture the reviewer's accept‑time `human_edit`. Add `editEvents.editMagnitude` (normalized char‑Levenshtein at capture) + `editEvents.reviewerId`; key edits to `contentPieceId`. **Filter** `source==='human_edit'` for edit‑rate.
* `methodologyPerformance.byHash` query — **pooled across owners**, grouped by `methodologyHash`, **min‑n gated** ("Not enough data yet" < \~80/arm), never a point estimate without showing n. Per‑creator data descriptive‑only.
* **Freeze the judge:** `JUDGE_VERSION` constant pins `0.6/0.4` weights + `HOOK_RUBRIC` + judge model; one CI snapshot test; `judgeVersion` rides in the fingerprint. **Never an optimization target** (it's near‑degenerate among passing posts).

## Out of scope (→ MAE‑222 / MAE‑223)

PostHog/flags/experiments; the user‑facing causal view; topic‑clustering (replaced by randomization in MAE‑222); engagement/ICP/booked‑calls outcome crons; the optimizer; wiring `converge.ts`.

## Invariants

Fingerprint born at resolve, copied at accept, never mutated (run = truth, piece copy = cache, integration‑tested to match) · `methodologyHash` not the version string is the identity · Convex serves every user number · run tables are workflow‑private, the uniform attribution surface is `contentObjects` + `outcomes` + the fingerprint.
