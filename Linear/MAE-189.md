- **Identifier:** MAE-189

**Why.** `context-os` was built by a strong context-engineering practitioner. We should mine it for ideas that can improve Maestro V2, Hermes memory, Fabro workflows, agent context selection, and durable learning loops.

**What.** Do a repo teardown of [https://github.com/jacob-dietle/context-os](<https://github.com/jacob-dietle/context-os>). Focus on architecture, primitives, workflows, context management patterns, persistence/indexing, agent ergonomics, and anything we should copy, adapt, or explicitly reject.

**Read first.**

* Repo: [https://github.com/jacob-dietle/context-os](<https://github.com/jacob-dietle/context-os>)
* Maestro swarm/factory docs and current decision registry before writing recommendations.

**Done when.**

* Repo structure and core abstractions are mapped.
* Key context-engineering patterns are summarized with concrete examples from the repo.
* A recommendation matrix is recorded: bring in now, spike later, reject, or watch.
* Any actionable Maestro/Fabro/Hermes changes are turned into linked follow-up Linear issues.
* The teardown is persisted as a durable Git artifact and linked back to this Linear issue.

**Suggested workflow.**

1. Clone/read the repo and inspect docs, examples, tests, and implementation entry points.
2. Compare against our current Maestro factory/swarm context flow.
3. Produce an evidence-backed teardown, not a vibe summary.
4. Route any durable verdicts through the decision registry / verdict propagation path if they affect future agent context selection.
