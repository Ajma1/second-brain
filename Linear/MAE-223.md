# Attribution Slice 3 — Slow-rung outcomes + optimizer + generalize to 2nd workflow (email)

- **Identifier:** MAE-223
- **Status:** Backlog
- **Assignee:** —
- **Team:** MAE
- **Updated:** 2026-06-09

The slow rungs and the payoff layers, built on the Slice‑1 spine + Slice‑2 platform.

**Design:** `docs/superpowers/specs/2026-06-09-attribution-versioning-design.md` §7, §8, §9 (Slice 3).

## Scope (each independently shippable)

1. **Slow‑rung outcome crons** → the generic `outcomes` ledger: engagement (HarvestAPI, free), and per‑type signals (open/reply/click for email, opt‑in for lead magnets). Engagement snapshots mirrored to PostHog for the time‑series chart (immutable → `argMax` latest in HogQL).
2. **ICP‑qualified engagement** (within‑client trend ONLY — never a cross‑client league table; it ranks audiences, not methods): net‑new `postEngagers` (HarvestAPI Post‑Reactions/Comments actors — different actors than today's profile pull) → firmographic enrichment (a **product‑owned** provider; `discolike` is a personal MCP, not product infra) → ZFC ICP score. \~$0.40–0.70/post; 40–70% enrich match. Cheapest first cut: scrape **commenters only** + LLM‑classify comment substance (\~$0.05/post), skip enrichment.
3. **Booked‑calls** ([cal.com/CRM](<http://cal.com/CRM>)): **per‑period, per‑client, directional only** — multi‑touch, sparse; never causal; kept visually separate from the randomized edit‑rate result.
4. **The optimizer** (governance‑gated, design §8): reads a **validated pooled outcome by experiment arm**. **Auto‑tune only voice‑neutral knobs**; every **output‑affecting** knob (hooks, templates, model, revise budget, rubrics) is **suggest‑only / A‑B‑gated with creator visibility**. The real risk is *gaming the reviewer* (Goodhart), so output‑affecting tunes require a validated outcome, never edit‑rate alone. Extends the existing `editEvents → ZFC classify → ruleCandidate → human promote` loop, now fingerprint‑attributed + **layer‑routed** (voiceCore vs type module).
5. **Generalize — the 2nd workflow (**`emailWriting`**)**: copies the golden skeleton, plugs into the existing fingerprint/`outcomes`/`acceptRun` contract + an `email` methodology module. Proves the generalization: attribution, edit‑rate, the outcomes ledger, and **cross‑content learning** light up for free. Validates that a `voiceCore` edit (from post edits) measurably lifts email outcomes — the cross‑channel compounding that is the moat.

## Validation links (cheap, do not defer the ability)

Because every rung is fingerprint‑keyed, "does edit‑rate predict engagement? does engagement track calls?" are queries that light up as volume accumulates. Defer the pipelines, not the validation — otherwise the program optimizes a proxy nobody pays for.
