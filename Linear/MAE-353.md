# Format-preserving content transfer — rich text fidelity across review and publish surfaces

- **Identifier:** MAE-353
- **Status:** Backlog
- **Assignee:** —
- **Team:** MAE
- **Updated:** 2026-06-20
- **URL:** https://linear.app/modern-agency-sales/issue/MAE-353/format-preserving-content-transfer-rich-text-fidelity-across-review

## User Story

**As a LinkedIn ghostwriter, I want draft content to transfer between the creation tool, review surface, and LinkedIn without losing formatting (line breaks, bold, spacing), so that I don't waste time re-formatting.**

## Source

Dalton Danks call (2026-06-18). Dalton uses Google Docs for one client and Notion for others. Transferring content between tools causes formatting loss.

> "if there was a way that I could take directly from what I've done in the Google doc to notion more cleanly, like, more directly. That would be fantastic"
> "That definitely takes more time than it needs to"

## Gap from Existing Issues

[MAE-246](https://linear.app/modern-agency-sales/issue/MAE-246/e1-8-notionairtable-exportsync-with-stable-post-ids-and-review-state) (Notion/Airtable export sync) covers sync with stable post IDs and review state, but does not address the formatting loss problem when content crosses platform boundaries.

## Prior Art (reference for concepts, not code to port)

**maestro-v2-3**:

* Uses BlockNote (`@blocknote/react`) as rich-text editor but content stored as plain strings — format is lost at storage layer
* `microsoft/markitdown` for ingest normalization (PDF/DOCX/HTML → markdown) — ingest only, no reverse path
* No Notion or Google Docs API integration

**mas-platform**:

* `types/content-presentation.ts` — 14 block types (paragraph, callout, list, quote, etc.)
* `UniversalContentRenderer.tsx` — renders all templates with CSS variable theming
* `utils/tiptap-serializer.ts` — bidirectional TipTap JSON ↔ markdown, preserving bold/italic/links
* `content-pipeline/unicode-formatting.ts` — LinkedIn-safe unicode for bold/italic (LinkedIn strips markdown)
* Future architecture doc plans migration to markdown for portability
* **No Notion or Google Docs API integration in either repo**

**maestro-agent-planning**:

* Blueprint spec (section 21.F): custom BlockNote schema with inline citation marks, serialization-for-publish pipeline (BlockNote → strip marks → join paragraphs → LinkedIn text)

## Implementation Notes

The real solution here is that Maestro IS the single surface — the review link ([MAE-241](https://linear.app/modern-agency-sales/issue/MAE-241/e1-3-client-review-link-comment-and-approve-without-an-account)) should eliminate the need for Google Docs/Notion entirely. Format fidelity within Maestro (editor → preview → LinkedIn publish) is the priority. LinkedIn unicode formatting from mas-platform is proven and needed. Notion/Google Docs connectors are lower priority if the review link works well.
