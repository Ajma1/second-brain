# bug: OAuth token refresh fails for headless CLI calls

- **Identifier:** MAE-483
- **Status:** Done
- **Assignee:** —
- **Team:** MAE
- **Updated:** 2026-08-01
- **URL:** https://linear.app/modern-agency-sales/issue/MAE-483/bug-oauth-token-refresh-fails-for-headless-cli-calls

## Problem

The staging OAuth server issues access tokens with \~60s TTL. The CLI stores a `refreshToken` but never auto-refreshes before headless calls, causing 401 UNAUTHENTICATED errors after \~1 minute.

`validOAuthCredential()` in `oauth-session.ts` has working refresh logic, and `resolveRuntimeEnvironment()` calls it for async headless commands. But the refresh silently fails because the credential was never persisted to Keychain in the first place (see [modernagencysales/maestro#3515](https://linear.app/modern-agency-sales/review/fixcli-persist-oauth-credentials-to-macos-keychain-94b1fdee9584), now merged).

## Expected behavior

After `maestro login --staging`, headless calls should work indefinitely by auto-refreshing the token before expiry.

## Current workaround

`MAESTRO_CREDENTIAL_STORE=file` + re-login before each call.

## Root cause

Keychain fix ([modernagencysales/maestro#3515](https://linear.app/modern-agency-sales/review/fixcli-persist-oauth-credentials-to-macos-keychain-94b1fdee9584)) is merged but the token TTL is still very short (\~60s). With the Keychain fix deployed, refresh should work — needs verification once staging deploys are back.
