# [ARCH-011] Add Fabro Convex Agent Mode runtime smoke workflow

- **Identifier:** MAE-200
- **Status:** Done
- **Assignee:** —
- **Team:** MAE

## Context

Fabro remains the deterministic software factory, but Temporal is the new product runtime being built and tested by the factory. We need a factory workflow that proves Temporal-backed code can run, resume, and produce evidence in Daytona.

Planning doc: `docs/operator/plans/active/2026-05-21-temporal-factory-daytona-integration.md`

## Scope

Add a factory capability named `factory.temporal-runtime-smoke` or equivalent.

Inputs:

* repo path
* package/workflow path
* task queue
* workflow type
* start input fixture
* expected final query/result
* event history policy
* worker command
* server command

Outputs:

* pass/fail
* workflow id/run id
* Temporal CLI/UI evidence
* worker logs
* event history summary
* replay/determinism result
* timeout/retry/cancellation evidence

## Acceptance Criteria

* The workflow starts a local Temporal dev server inside the sandbox.
* The workflow starts a worker for the target task queue.
* The workflow starts a sample workflow and verifies query/state progression.
* The worker is killed/restarted and the workflow still completes.
* Event history inspection proves token deltas are not spammed into Temporal history.
* Failures are actionable for missing CLI, port conflicts, worker connection failure, wrong registrations, determinism failure, missing timeout/retry policy, and missing gate evidence.
* Logs, workflow ids, run ids, and event history summary are persisted as Fabro evidence.
