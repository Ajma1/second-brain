# Product Brain native corpus artifact and read bridge cutover

- **Identifier:** MAE-367
- **Status:** In Progress
- **Assignee:** Tim Keen
- **Team:** MAE
- **Updated:** 2026-06-24
- **URL:** https://linear.app/modern-agency-sales/issue/MAE-367/product-brain-native-corpus-artifact-and-read-bridge-cutover

## User Story

As a Maestro operator, I want the Product Brain read-only bridge to prefer native, source-backed Product Brain corpus output before falling back to the transitional `maestro-score` bridge, so Hermes can validate Convex as the Product Brain context source without exposing mutating writes.

## Context

[MAE-264](https://linear.app/modern-agency-sales/issue/MAE-264/e5-3-agent-context-pack-cited-role-scoped-always-current) added the read-only Product Brain bridge and API surface. [modernagencysales/maestro#660](https://linear.app/modern-agency-sales/issue/MAE-368/product-brain-native-corpus-artifact-and-read-bridge-cutover) adds append-only version ledgers for claims and knowledge files. The remaining cutover gap is runtime corpus ownership: `/Users/headless/.hermes/scripts/maestro-product-brain-mcp.sh` currently sets `MAESTRO_BUSINESS_CONTEXT_MCP=/Users/headless/.hermes/scripts/brain-mcp.sh`, which keeps `maestro-score` in the default Product Brain bridge path.

The target for this slice is deliberately narrow: add a native source-backed corpus artifact path and make the bridge prefer it for read/search/context-pack operations. `maestro-score` can remain a configured rollback/fallback, but the Product Brain bridge should no longer require it for successful cited output when native corpus data exists.

## Scope

* Add a repo-owned native Product Brain corpus artifact format for source-backed context entries.
* Add deterministic read/search/context-pack rendering over that native corpus artifact.
* Update the read-only MCP bridge so native corpus output wins over `MAESTRO_BUSINESS_CONTEXT_MCP` fallback.
* Update the Hermes host wrapper so the transitional business bridge is opt-in fallback rather than the default Product Brain bridge dependency.
* Document the native corpus path, fallback behavior, and non-mutating tool allowlist.

## Acceptance

* `search_brain`, `contextPack`, `grepVault`, `readNote`, and `listNotes` expose only read/search/context-pack behavior.
* When native corpus data exists, bridge output contains source-backed native corpus citations and does not report `businessContextSource`.
* When native corpus data is absent and an explicit fallback bridge is configured, the bridge can still use the transitional read-only business context source.
* No Product Brain mutating writes are exposed to ordinary coding workers.
* Hermes brain MCP is not repointed by this story.
* `HEADLESS_BRAIN_MCP=/Users/headless/.hermes/scripts/maestro-product-brain-mcp.sh headless-brain-brief --self-check --json` passes.
* `headless-product-brain-readiness --json` passes.

## Out of Scope

* Full automated adapters for every source system.
* Repointing `/Users/headless/.hermes/config.yaml`.
* Product UI for corpus browsing.
* Semantic/vector search.
* Removing `/Users/headless/.hermes/scripts/brain-mcp.sh`; it remains rollback/prior art until native ingestion is fully populated.
