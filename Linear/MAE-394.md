# Product Brain supervised ingest and extraction workflow

- **Identifier:** MAE-394
- **Status:** Backlog
- **Assignee:** Tim Keen
- **Team:** MAE
- **Updated:** 2026-07-24
- **URL:** https://linear.app/modern-agency-sales/issue/MAE-394/product-brain-supervised-ingest-and-extraction-workflow

## User Story

As a ghostwriter, I want pasted text and URLs to enter the canonical Brain through supervised ingestion, extraction, grounding, and review, so accepted context packs are populated from cited source material rather than manual seed files.

## Context

Brain v1 simple intentionally split the read/lifecycle API from the supervised ingestion workflow. Current API surface exposes reads, claim lifecycle, knowledge files, sources, and extraction run reads. The missing product slice is the durable workflow that implements `brain.ingestText` / `brain.ingestUrl`, chunks source text, extracts candidate claims, validates grounding, writes citations, and routes candidates to review.

## Scope

* Implement durable workflow stages: INGEST, EXTRACT, GROUND, ENRICH, SERVE trace points.
* Add `brain.ingestText` and `brain.ingestUrl` capabilities as supervised entry points, not generic note writes.
* Use `adapters/llm.ts` for model calls and deterministic checks for grounding/fingerprint/idempotency.
* Store candidate claims and citations in canonical Brain v1 tables with workspace/client scoping.
* Connect to [MAE-262](https://linear.app/modern-agency-sales/issue/MAE-262/e5-1-claim-candidate-review-promotereject-with-auditable-change-ledger) review/lifecycle semantics for promotion/rejection.

## Acceptance

* Re-ingesting the same source is idempotent.
* Invalid quotes fail deterministic grounding and cannot be accepted.
* Extraction runs record stats and failure/flagged status.
* Accepted claims appear in `brain.dump` context packs with citations.
* No `writeNote`/`appendNote`-style generic writes are introduced.
