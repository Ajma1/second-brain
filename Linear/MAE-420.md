- **Identifier:** MAE-420
- **Status:** Backlog

Source spec: `docs/superpowers/specs/2026-06-28-linkedin-beneficial-adjacency-map-design.md`

## Goal

Make graph v2 generation robust when optional inputs such as engagement samples or embeddings are missing.

## Files

Modify:

* `tooling/corpus/beneficial-adjacency/graph-v2.mts`
* `tooling/corpus/linkedin-beneficial-adjacency.mts`
* `tooling/corpus/linkedin-beneficial-adjacency.test.mts`

## Work

Ensure graph analysis creates or registers empty compatible tables for optional artifacts when files are absent:

* semantic embedding edges
* audience edges
* audience overlap edges
* post commenters/reactors
* optional review labels or seed labels

Missing optional data should lower confidence and add known limitations, not fail the run.

## Constraints

* Required corpus/template inputs may still fail loudly; optional enrichment inputs should not.
* Low-evidence rows must be demoted or sent to `low_confidence_candidates.csv`.
* The output schema should remain stable whether optional inputs are present or absent.

## Verification

Run:

```bash
rtk env HOST_TEST_MAX_LOAD_1M=100 host-test-slot --class focused pnpm exec tsx --test tooling/corpus/linkedin-beneficial-adjacency.test.mts
```

Expected: PASS.

## Acceptance Criteria

* Tests cover graph generation without embeddings and without engagement artifacts.
* Outputs are still written with stable schemas and appropriate confidence/limitations.
