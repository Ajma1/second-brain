# [E1-6.1] stalled-review detection — pure predicate + property tests

- **Identifier:** MAE-307
- **Status:** Backlog
- **Assignee:** —
- **Team:** MAE
- **Updated:** 2026-06-17
- **URL:** https://linear.app/modern-agency-sales/issue/MAE-307/e1-61-stalled-review-detection-pure-predicate-property-tests

First slice of MAE-244 — ships the pure detection predicate.

**In scope (this PR):**

* `packages/convex/convex/checks/stalledReview.ts` — pure function `isStalledReview({ piece, now, dueAt? })` returning `{ stalled, missedSlot, reason }`. Threshold pinned as `STALL_THRESHOLD_MS` invariant constant.
* `packages/convex/convex/checks/stalledReview.test.ts` — fast-check property tests + boundary tests.

**Out of scope (later slices):**

* Capability layer (`capabilities/stalledReviews.ts`) — workspace-scope detection over all in-review pieces.
* Workflow / scheduler integration to fire BEFORE the publish slot is missed.
* Audit-trail persistence + notification surface.
* UI surface (Today view / cockpit exception card).

**Schema-gap note (does not block this slice):**
`pieces.status` has no explicit `review` literal — the lifecycle is `draft → linted → approved → scheduled → published`. We treat `linted` as the in-review state (post-lint, pre-approval gate) and use `pieces.updatedAt` as the "review window started" timestamp. `pieces` carries no `dueAt`; `batches.dueAt` does, so the caller (next-slice capability) joins through the batch. The predicate keeps its time inputs as injected `number`s so schema choices live above it.

Pattern follows existing `checks/` layer: pure TS, no `ctx`, no I/O, time injected, fast-check property-tested. Module header per `maestro/require-module-header`; threshold annotated per `maestro/policy-is-data` (deploy is the right change-path for v1; per-workspace override lands with the capability slice).
