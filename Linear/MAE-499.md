# bug: Brain Atlas only shows 1 page despite multiple active pages in workspace

- **Identifier:** MAE-499
- **Status:** Done
- **Assignee:** —
- **Team:** MAE
- **Updated:** 2026-08-01
- **URL:** https://linear.app/modern-agency-sales/issue/MAE-499/bug-brain-atlas-only-shows-1-page-despite-multiple-active-pages-in

## Problem

The Brain Atlas tab shows "Pages: 1, Links: 0, Orphans: 1" and renders only a single "Untitled" node, despite the workspace having 7 active, non-archived Brain pages.

Hard refresh (Cmd+Shift+R) does not fix it.

## Evidence

Query against `brainPages` table confirms 7 pages exist for workspace `pn72vh8eytbxmqxx9smhd612558b4e3j`, all with `status: "active"` and `isArchived: false`:

* Untitled (July 24)
* Susan Hansted - voice and positioning brief (July 28)
* 3x Untitled (July 31)
* Susan Hansted — ICP Pain Points (July 31)
* Susan Hansted — Sample LinkedIn Posts (July 31)

## Root cause investigation

The Atlas query at `capabilities/brain/graph.ts:101-107` uses index `by_workspace_status_updated`:

```typescript
ctx.db.query("brainPages")
  .withIndex("by_workspace_status_updated", (q) =>
    q.eq("workspaceId", input.workspaceId).eq("status", "active"),
  )
  .take(ATLAS_PAGE_READ_LIMIT)
```

The data is correct (all pages are active, same workspace). Possible causes:

* Index not covering all pages (index might require additional fields like `updatedAt` that newer pages don't have in the expected format)
* The manually created pages might be missing a field the index expects
* The Atlas page limit is filtering them out
