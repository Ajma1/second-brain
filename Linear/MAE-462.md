# Alpha onboarding CLI and posts rename execution stack

- **Identifier:** MAE-462
- **Status:** Done
- **Assignee:** Tim Keen
- **Team:** MAE
- **Updated:** 2026-07-08
- **URL:** https://linear.app/modern-agency-sales/issue/MAE-462/alpha-onboarding-cli-and-posts-rename-execution-stack

## Context

We need to move the alpha onboarding design into small PRs that can go green and merge.

Design spec committed in repo context:

* `docs/superpowers/specs/2026-07-06-alpha-onboarding-cli-design.md`

## Goal

Build the terminal-first alpha onboarding path for manually onboarding ghostwriters and their client workspaces, with the `pieces -> posts` rename as a prerequisite so imports and product language stay aligned.

## Scope

* Rename generated-post storage/API terminology from `pieces` to `posts` before import work depends on it.
* Audit staging frontend surfaces for real DB wiring vs intentional demo/static state.
* Add internal-alpha workspace provisioning/granting substrate for Growth Team access to client workspaces.
* Add `pnpm maestro onboard` artifact/manifest flow.
* Add local/Notion-ready context collection and packaging artifacts.
* Add bounded idempotent import capabilities only where existing capabilities are insufficient.
* Add runbook and verification evidence.

## Non-goals

* No admin console.
* No silent client account creation during alpha.
* No direct DB writes from CLI.

## Acceptance

* Work is split into small Graphite-friendly PRs.
* Each PR cites the approved plan bundle for this issue.
* PRs are green in CI before merge.
* Final result supports repeatable alpha onboarding from the terminal with dry-run and apply modes.
