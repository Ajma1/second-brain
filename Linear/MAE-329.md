# [ARCH] arch-test — joined-row workspace guard ratchet for cross-tenant batch/piece reads

- **Identifier:** MAE-329
- **Status:** Backlog
- **Assignee:** —
- **Team:** MAE
- **Updated:** 2026-06-17
- **URL:** https://linear.app/modern-agency-sales/issue/MAE-329/arch-arch-test-joined-row-workspace-guard-ratchet-for-cross-tenant

## Why

PR #178 (MAE-326, `feat/review-exceptions-capability-MAE-326`) shipped an instance fix for a RED contract-review TENANCY finding: `reviewExceptions.ts` read `batch.dueAt` after joining through `pieces.batchId` without verifying that the joined batch belongs to `ctx.workspace._id`. That is an IDOR-class data leak — a cross-workspace batch could influence whether a piece flagged `missed_slot`.

The instance fix landed in PR #178 (commit `028fbea`):

* `packages/convex/convex/capabilities/reviewExceptions.ts` — every field read on the joined batch is now gated on `batch.workspaceId === input.workspaceId`; otherwise the value is treated as `null` (mirrors `edits.assertPieceInWorkspace` — one opaque outcome, no enumeration leak).
* New behavioural test in `reviewExceptions.test.ts` pins the cross-tenant case.

Per RATCHET_ESCAPE (PR #155 / `feat/coedit-routine-doc-MAE-240`), the gate work is split out of the instance-fix PR and tracked here.

## Charter alignment

* AGENTS.md ratchet rule: "Every found pattern becomes a gate." A bad-pattern instance found in review = the same PR (or immediate follow-up) makes the pattern structurally impossible.
* Contract-review marked this finding with `mechanicalGateCandidate: arch-test`.
* Maps to the existing `maestro/no-caller-supplied-identity` family — same IDOR class, but specifically about joined-row field reads.

## Scope (ratchet PR)

A single PR that adds:

1. **arch-test** (under `tooling/quality/` — alongside `check-contract-review-surface.mts`, `check-workflow-shape.mts`, etc.) that statically scans `packages/convex/convex/capabilities/**/*.ts` for the pattern:
   * `ctx.db.get("<table>", <id>)` (or `await ctx.db.get(...)`) where the resulting binding's fields are subsequently read,
   * and the local scope does NOT contain a `<binding>.workspaceId === ctx.workspace._id` (or `=== input.workspaceId`) check between the `db.get` and the first field read.
   * The check should treat any joined-row dereference (`.dueAt`, `.title`, `.status`, etc.) the same — the rule is "verify workspace membership before reading any field on a joined row."
   * Allowlist mechanism: a single-line comment annotation (e.g. `// arch-allow: joined-row-no-workspace-check — <reason>`) lets one-off legitimate cases opt out with an audit trail. Each allowlist entry MUST cite the reason in the comment.
2. **docs/rule-coverage.md** row — one line, name + scope + enforcement layer (arch-test).
3. **tooling/quality/check-config-drift.mts** pin — register the new arch-test in the pinned-strength manifest so the gate cannot be silently weakened.
4. **Wire into** `pnpm check:gates` — the `verify` chain already runs `check:gates`; the new arch-test must be invoked there (and in CI completeness — `check-ci-completeness.mts`).
5. **Validation** — re-running the gate against `main` (post-#178) should be green. Intentionally regressing `reviewExceptions.ts` (remove the workspaceId check) should make the gate RED. Add a `.test.mts` for the gate that pins both green and red cases against fixtures.

## Out of scope (this issue)

* Any product-surface change (the instance is already fixed in #178).
* Broader joined-row guards beyond capabilities/* (workflows, adapters — separate sub-issue if instances are found).
* Public-surface IDOR rules — already covered by `maestro/no-caller-supplied-identity`.

## Acceptance

* `pnpm verify` green.
* `pnpm check:gates` runs the new arch-test.
* Gate fixture test: green for the current tree; red for a synthetic regression that removes the workspaceId check.
* `docs/rule-coverage.md` updated.
* `tooling/quality/check-config-drift.mts` updated.
* PR opened in isolation (no instance-fix changes; #178 is the instance fix).
