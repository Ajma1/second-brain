# feat: enable client provisioning on operator launch page

- **Identifier:** MAE-482

## Context

The `/onboarding` operator launch page has client provisioning permanently disabled with the message:

> "Client provisioning is unavailable for this launch because the server-owned grant policy is not approved."

The backend mutation (`provisionAlphaWorkspace`) and command binding already exist and work. The form fields and button just need to be wired up.

## PR

* [#3603](<https://github.com/modernagencysales/maestro/issues/3603>) — adds form fields (request key, client name, LinkedIn URL, org ID, initial credits) and connects the existing `provisionAlphaWorkspace` mutation
* Was merged then reverted by agent ([modernagencysales/maestro#3604](https://linear.app/modern-agency-sales/review/revertonboarding-disable-operator-client-provisioning-b13b8f15f7fd)) because the change was out of band with the current launch readiness process

## When to re-land

Once the server-owned grant policy is approved and the launch readiness process is complete, re-land [#3603](<https://github.com/modernagencysales/maestro/issues/3603>) (or the updated v2 branch `feat/enable-onboarding-provisioning-v2`).

## Why this matters

Without this, new ghostwriter workspaces can only be provisioned via the CLI with an org-level API key, which requires org admin access and has UX friction. Enabling the UI form unblocks beta onboarding.
