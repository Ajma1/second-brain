# [ARCH-020] Park Temporal/Hatchet worker-restart bakeoff behind Convex hardening

- **Identifier:** MAE-216
- **Status:** Done
- **Assignee:** —
- **Team:** MAE
- **Updated:** 2026-05-21
- **URL:** https://linear.app/modern-agency-sales/issue/MAE-216/arch-020-park-temporalhatchet-worker-restart-bakeoff-behind-convex

## Context

[MAE-208](https://linear.app/modern-agency-sales/issue/MAE-208/arch-019-build-side-by-side-hatchet-and-temporal-content-runtime) produced a deterministic local simulation for the content-runtime contract. It proved the product invariants, but it did not measure real Temporal or Hatchet durable-service behavior.

This issue is the real-service bakeoff that lets [MAE-203](https://linear.app/modern-agency-sales/issue/MAE-203/arch-014-run-neutral-hatchet-vs-temporal-runtime-decision-for-content) make a defensible runtime decision.

## Scope

Run the same LinkedIn content-object workload from [MAE-208](https://linear.app/modern-agency-sales/issue/MAE-208/arch-019-build-side-by-side-hatchet-and-temporal-content-runtime) against real local or sandbox services for both candidates:

* Temporal TypeScript worker + local Temporal service.
* Hatchet worker + local/self-hosted Hatchet service.
* Shared deterministic content gate engine.
* App-owned stream and evidence log.
* Same model-provider fixture by default.

## Required tests

* Start batch and stream provisional deltas.
* Persist provisional object versions outside runtime history.
* Fail deterministic gates on at least one object.
* Repair only the affected object and re-run gates.
* Block export before ready.
* Kill/stop/evict a worker during drafting and during repair.
* Restart worker and prove no lost object state, stream event, gate report, or ready promotion.
* Reconnect stream from cursor after restart.
* Capture setup, operational complexity, idempotency burden, and agent-legibility notes.

## Outputs

* `reports/temporal-real-service-run.json`
* `reports/hatchet-real-service-run.json`
* `reports/real-service-comparison.json`
* README/runbook for local service startup.
* Decision handoff comment on [MAE-203](https://linear.app/modern-agency-sales/issue/MAE-203/arch-014-run-neutral-hatchet-vs-temporal-runtime-decision-for-content).

## Success metrics

* first status event latency
* first provisional delta latency
* time to first provisional post
* time to first lint-passed ready post
* repair success rate
* failure clarity score
* restart/replay correctness
* implementation complexity
* deployment complexity
* ability to share deterministic rules between product runtime and Fabro gates

## Stop gate

Do not declare Temporal or Hatchet the final runtime until both candidates run the same real-service contract or one candidate fails setup in a documented, reproducible way.
