# Product Brain native corpus import and bridge fallback removal

- **Identifier:** MAE-393
- **Status:** Done
- **Assignee:** —
- **Team:** MAE
- **Updated:** 2026-08-01
- **URL:** https://linear.app/modern-agency-sales/issue/MAE-393/product-brain-native-corpus-import-and-bridge-fallback-removal

## User Story

As a Maestro operator, I want native business corpus entries imported into the canonical Brain v1 store, so the read-only bridge no longer depends on the transitional `maestro-score` fallback for business context.

## Context

[MAE-368](https://linear.app/modern-agency-sales/issue/MAE-368/product-brain-native-corpus-artifact-and-read-bridge-cutover) adds a native source-backed corpus artifact and makes the bridge prefer it when present. The next ownership step is to import/export that corpus through canonical Brain v1 rows (`sources`, `sourceChunks`, `claims`, `claimCitations`, `knowledgeFiles`) rather than treating the JSON seed or `maestro-score` as a store.

## Scope

* Define a supervised import path from native corpus artifacts into Brain v1 source/claim tables.
* Preserve citation/source paths and workspace/client scoping.
* Make bridge output come from canonical Brain exports where available.
* Keep `maestro-score` as explicit rollback only until import coverage is sufficient, then remove it from the default candidate bridge path.
* Add readiness/eval coverage for source-backed output after fallback removal.

## Acceptance

* Native corpus entries can be represented as canonical Brain rows with citations.
* The bridge can serve cited business context without `MAESTRO_BUSINESS_CONTEXT_MCP` when imported corpus data exists.
* Fallback behavior is explicitly opt-in rollback, not default runtime dependency.
* No generic worker write tools are exposed.
