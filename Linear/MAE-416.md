## Goal

Create the CLI that runs the local DuckDB/artifact pipeline in deterministic stages.

## Files

Create:

* `tooling/corpus/linkedin-beneficial-adjacency.mts`

Modify:

* `package.json`
* `tooling/corpus/linkedin-beneficial-adjacency.test.mts`

## Work

Implement CLI modes for at least:

* `plan`: read existing corpus analytics outputs and write sample/embedding/run plans without provider calls.
* `analyze`: build graph v2 tables and recommendation artifacts from local inputs.
* `review`: assemble review queue/eval artifacts from recommendations and negative controls.

The CLI should write `run_config.json`, `stage_state.json`, `lineage_manifest.json`, `privacy_manifest.json`, `budget_ledger.json`, and observability summaries in a run directory.

## Constraints

* Convex is the source/serving layer, not the analytics engine.
* Provider stages must declare expected requests/tokens/USD and stop before live calls when over budget.
* Runs must be resumable and deterministic for a given config/cache/corpus snapshot.
* Commands must use `rtk`; tests through `host-test-slot`.

## Verification

Run:

```bash
rtk env HOST_TEST_MAX_LOAD_1M=100 host-test-slot --class focused pnpm exec tsx --test tooling/corpus/linkedin-beneficial-adjacency.test.mts
```

Expected: PASS.

## Acceptance Criteria

* CLI creates the required manifests/ledgers/stage files in a tiny fixture test.
* Plan/analyze/review modes can be invoked independently.
* Package script is added for the CLI.
