## Goal

Document the Harvest engagement endpoint contracts that the adapter and sampler will rely on.

## Files

Modify `docs/api-references/harvest-api.md`.

## Work

Add sections for:

* `GET /linkedin/post-comments`
* `GET /linkedin/post-reactions`
* `GET /linkedin/profile-comments`
* `GET /linkedin/profile-reactions`

For each endpoint, include expected query params, pagination behavior, and normalized fields. Also add Key Gotchas stating that engagement endpoints must go through `packages/convex/convex/adapters/harvest.ts`, sampling must remain sparse, and actor identity normalization must prefer provider/profile ID, canonical LinkedIn URL, public identifier, then salted fallback fingerprint.

## Constraints

* Do not add direct Harvest calls outside the adapter boundary.
* Do not imply that every post should be enriched; engagement sampling is sparse.
* Commands in docs should use `rtk ...`.

## Verification

```bash

```

Expected: all four endpoint names appear.

* Endpoint contracts are documented enough to implement adapter tests.
* Sparse sampling and privacy identity rules are explicitly called out.
