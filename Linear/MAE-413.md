## Goal

Build a provider-agnostic embedding layer that is cache-first, budget-aware, and reusable as the corpus grows.

## Files

Create:

* `tooling/corpus/beneficial-adjacency/embedding-provider.mts`
* `tooling/corpus/beneficial-adjacency/embedding-cache.mts`

Modify:

* `tooling/corpus/linkedin-beneficial-adjacency.test.mts`

## Work

Implement:

* OpenAI-compatible HTTP embedding client with configurable base URL, API key, and model.
* Cache keys derived from model, input kind, and stable content hash.
* Input selection that dedupes normalized text and caps total inputs.
* Cache merge that preserves existing embeddings and adds new rows by key.
* Embedding input kinds for creator profile text, recent post samples, outlier samples, post template text, hook text, and cluster/topic text.

## Constraints

* No provider calls when cache satisfies inputs.
* Provider calls must be guarded by budget ledger before execution.
* Cache entries must include model, input kind, content hash, source ID, text, embedding, and created timestamp.
* Keep implementation provider-agnostic so OpenRouter/OpenAI-compatible endpoints can be swapped.
