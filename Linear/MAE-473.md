# Client review batches — approve N posts, canonical annotations, optional LinkedIn OAuth

- **Identifier:** MAE-473
- **Status:** Backlog
- **Assignee:** —
- **Team:** MAE
- **Updated:** 2026-07-11
- **URL:** https://linear.app/modern-agency-sales/issue/MAE-473/client-review-batches-approve-n-posts-canonical-annotations-optional

## Outcome

As an agency operator, I can select N LinkedIn posts and send one private no-login review link. The client can approve posts quickly, request precise edits/annotations, and optionally connect the correct LinkedIn account from that same review experience if the agency permits it.

## Current state

The polished `/client-review/$token` screen already exists and should be surfaced rather than reinvented. It includes the multi-post stepper/progress experience, selected-text feedback composer, approve/next flow, undo affordance, and completion state.

Production gaps:

* live review tokens currently authorize a single post only;
* multi-post portal state is fixture/local rather than durable;
* approval and change-request actions in the portal are local UI transitions rather than persisted commands;
* sender links in `/approvals` are preview-style placeholders;
* there is no bulk “send remaining N posts for review” workflow;
* optional LinkedIn OAuth is not available through review grants.

## Scope

* Add review batches/items so one token can authorize an ordered set of posts.
* Pin immutable document versions for every shared review item/round.
* Route all feedback and selected-text markup into existing `documentAnnotations`; do not create a second comments/feedback lifecycle.
* Delegate approvals to the existing post approval implementation after token, item, version, and annotation guards pass.
* Reuse the existing `/client-review/$token` public route and Notion Kit review UI blocks.
* Add sender UI for “Send remaining N for review” and choosing a subset.
* Update `/approvals` into a real Client Reviews management surface backed by batches/items/annotations.
* Add optional LinkedIn OAuth from the review link only when the batch permits it and the client persona lacks a healthy connected account.
* Reuse existing LinkedIn OAuth provider/state/workflow/encrypted storage/conflict/audit paths; raw review tokens must never be embedded in OAuth state.

## Non-goals

* No second editor.
* No new client comments table or shadow markup process.
* No automatic publishing/scheduling merely because a post is approved or OAuth succeeds.
* No authenticated workspace chrome for the no-login client route.

## Acceptance

* An operator can send one link for N eligible posts and copy/open it.
* A clean browser with no Maestro session can review all N posts from pinned versions.
* Approve and request-change actions survive reload.
* Requested changes appear in Studio as ordinary pending `documentAnnotations` with client-review provenance and existing accept/reject/version behavior.
* Approval is version-specific and fails closed when unresolved client-origin annotations or stale versions exist.
* The existing public review screen is used with live data; fixture sibling posts and local-only mutations are removed from live paths.
* Optional LinkedIn connection appears only for eligible review grants, reuses the existing OAuth stack, returns safely to the same review portal, and does not block approval.
* Revoked/expired links and OAuth replay/denial/conflict paths fail closed.
