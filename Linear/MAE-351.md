# Automated fact-checking — proactive transcript-vs-draft mismatch detection

- **Identifier:** MAE-351
- **Status:** In Review
- **Assignee:** Tim Keen
- **Team:** MAE
- **Updated:** 2026-06-20
- **URL:** https://linear.app/modern-agency-sales/issue/MAE-351/automated-fact-checking-proactive-transcript-vs-draft-mismatch

## User Story

**As a LinkedIn ghostwriter, I want the system to automatically cross-reference every claim in a draft against the original transcript and flag mismatches, so that I don't have to manually read through transcripts to verify accuracy.**

## Source

Dalton Danks call (2026-06-18). This is the single biggest time sink — Dalton estimates the manual fact-checking and AI-ism removal adds 10-20 minutes per post on top of what should be a fast process.

> "I'm basically doing that myself that's what I'm hoping to take off my plate that's pretty much the process and why it takes I think the extra you know 20 minutes that it doesn't really need"

## Gap from Existing Issues

[MAE-290](https://linear.app/modern-agency-sales/issue/MAE-290/e1-10-review-transparency-claims-sources-and-golden-nugget-insight-on) (review transparency) shows claims and sources on each draft. [MAE-262](https://linear.app/modern-agency-sales/issue/MAE-262/e5-1-claim-candidate-review-promotereject-with-auditable-change-ledger) (claim candidate review) handles claim extraction and promotion/rejection. Neither provides an automated **verification step** that proactively surfaces transcript-vs-draft mismatches before the ghostwriter reviews. The ghostwriter shouldn't have to hunt for problems — the system should surface them.

## Prior Art (reference for concepts, not code to port)

**maestro-v2-3** (fully built end-to-end):

* `brain/factCheck.ts` — `runFactCheck`: snapshots draft, extracts claims via Haiku, locates claim spans with `indexOf`, traces to Score claims
* `lib/draftFactCheck.ts` — pure helpers: `parseFactCheckOutput()`, `locateClaimSpan()`, `deterministicGroundingMatch()`, `resolveClaimStatus()`
* `draftFactChecks` table — stores per-post results with frozen `draftContent`, claims with status (grounded/ungrounded/opinion), source citations
* UI: `fact-check-client.tsx` — inline highlights (green=grounded, amber=ungrounded), numbered citation rail with hover sync
* Currently user-triggered; auto-blocking pipeline stage deferred

**mas-platform**:

* `trigger/seo-quality-check.ts` — scores on accuracy dimension ("Are claims supported by data?")
* DFY checklists include "No hallucinated facts" but as human review items, not automation

## Implementation Notes

The v2-3 UI pattern (inline highlights with citation rail) is excellent UX — worth replicating cleanly. The core pipeline (extract claims → locate spans → match against source → classify) is sound. Consider making this run automatically after every draft generation rather than user-triggered.
