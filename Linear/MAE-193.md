## Why

Human review should improve the system over time. Repeated edits must become memory, deterministic rules, prompt/model changes, or eval fixtures.

## Scope

* Capture before/after/diff/editor/timestamp/object id/version id.
* Classify edit as taste, deterministic defect candidate, prompt/eval candidate, or no-op.
* Promote approved deterministic defects into `@maestro/content-gates` config plus fixtures.
* Run the same gate package in Temporal Activity and Fabro/CI.

## Success Metrics

* 100% of relevant human edits store structured diff evidence.
* Useful classification accuracy is at least 80% on a hand-labeled sample.
* A promoted rule creates at least one positive and one negative fixture.
* Same input and rule-set hash produce identical gate reports in product runtime and Fabro/CI.
* Rule authors do not need to edit Temporal or Fabro workflow code.
