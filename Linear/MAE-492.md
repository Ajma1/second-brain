# feat: prevent output degradation on re-edits (iteration stability)

- **Identifier:** MAE-492
- **Status:** Backlog
- **Assignee:** —
- **Team:** MAE
- **Updated:** 2026-07-30
- **URL:** https://linear.app/modern-agency-sales/issue/MAE-492/feat-prevent-output-degradation-on-re-edits-iteration-stability

## User need

When iterating on AI-generated content (asking for rewrites, tweaks, refinements), the output quality degrades. Each edit cycle moves further from the original voice and introduces hallucinations.

**Aman's words:** "hallucinations on re-edits" — output degrades when iterating

## What this solves

Ghostwriters iterate heavily on drafts. In a single-prompt tool, each "try again" or "make this change" loses context from the previous version. The AI starts hallucinating or drifting from voice.

## How Maestro already partially addresses this

* **Staged workflow** — each stage (idea, tone, draft, check) is independent, so fixing one stage doesn't regenerate everything
* **Quality evaluation** — the 7-dimension scoring catches drift on each iteration
* **Voice brief** — pinned for the entire generation, doesn't change between edits

## What's missing

* **Version diffing** — show what changed between iterations so the writer can catch drift
* **Pinned context per edit** — when a user requests a change, carry forward the exact previous draft + the specific change request, not a re-summarized context
* **Re-lint after manual edits** — if the writer edits the draft manually, re-run deterministic checks to catch any voice violations introduced by human edits

## ICP evidence

* Aman (call 15): hallucinations on re-edits, output degrades when iterating
* Ali (call): editing drafts still takes 30+ minutes — iteration is the core workflow
* Jon Keel (call): humanizes all AI output manually — heavy iteration expected
