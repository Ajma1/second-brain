# [Process] Require human-readable prior-art report before Fabbro plan/codegen

- **Identifier:** MAE-364
- **Status:** Done
- **Assignee:** Tim Keen
- **Team:** MAE
- **Updated:** 2026-06-22
- **URL:** https://linear.app/modern-agency-sales/issue/MAE-364/process-require-human-readable-prior-art-report-before-fabbro

## Problem

[MAE-292](https://linear.app/modern-agency-sales/issue/MAE-292/e6-8-conversational-entry-point-chatgpt-style-surface-on-the-e6-3) exposed a workflow gap: `prior-art-dossier.json` can exist while the generated implementation plan still fails to explain what prior art was inspected, adopted, rejected, or how it shaped the plan.

## Scope

Require `story-to-spec` to produce a human-readable `prior-art-report.md` alongside the structured dossier. Require `plan` and plan-required metadata to carry and hash that report before an approved stack can be submitted.

## Acceptance

* `pnpm maestro story-to-spec <issue>` writes `prior-art-report.md` with explicit sections for current repo, external/v1 prior art, adopt, reject, implementation implications, and weak/uninspected evidence.
* `pnpm maestro plan <issue>` refuses or fails quality when a prior-art story has no non-shallow report.
* Approved plan bundles include `prior-art-report.md` and `stack-plan.meta.json` hashes it.
* Plan-required checks verify the report path/hash.
* Workflow prompts mention the report as a required review artifact before code generation.
