# Attribution Slice 2 — Measurement platform (PostHog traces + randomized experiments + Methodology-Performance view)

- **Identifier:** MAE-222
- **Status:** Done
- **Assignee:** Tim Keen
- **Team:** MAE
- **Updated:** 2026-06-10
- **URL:** https://linear.app/modern-agency-sales/issue/MAE-222/attribution-slice-2-measurement-platform-posthog-traces-randomized

The genuinely separable **second system**, built on top of the Slice‑1 fingerprint spine. This is where attribution claims become **causal**.

**Design:** `docs/superpowers/specs/2026-06-09-attribution-versioning-design.md` §4, §7, §9 (Slice 2).

## Why separate from [MAE-219](https://linear.app/modern-agency-sales/issue/MAE-219/llm-observability-prompt-evals-posthog-convex-integration)

The fingerprint spine (Slice 1, [MAE-219](https://linear.app/modern-agency-sales/issue/MAE-219/llm-observability-prompt-evals-posthog-convex-integration)) is Convex-only and produces an **observational/directional** edit‑rate number. Randomized experiments + the measurement platform are a whole greenfield system (zero PostHog refs in convex today) and must not be built before the spine carries one number end‑to‑end. **Decoupling:** the planes share only the fingerprint *value*, never call each other.

## Contract (fixed in the design)

Convex = system of record; **PostHog = append‑only analytics/experiment mirror**. PostHog events are immutable, so it can never hold a mutable outcome. The product UI **never reads an authoritative number from PostHog**; attribution joins depend on the stamped fingerprint *prop*, not PostHog's identity graph.

## Scope

1. **Gate first — a 10‑line spike:** confirm `@posthog/convex` (v2.0.19, GA) captures a fingerprint‑tagged `$ai_generation` from a `postWriting` step, in the **default isolate**, **non‑blocking** via `ctx.scheduler`, queryable in HogQL on Convex 1.40. Do not build further until this is verified live.
2. **Trace observability** (immediate value): `posthog.capture("$ai_generation", { $ai_trace_id: workflowId, ...fingerprint, tokens })` per AI call. Send text **hashes/refs**, not bodies (1 MB event cap). Emit **per‑final**, not per‑candidate (cost).
3. **Flag‑assigned randomized experiments:** server‑side flag eval in `resolveContext` → write `experimentId`/`variant` into the fingerprint → fire manual `$feature_flag_called` exposure. **Bucket per‑piece** (independent draws), not per‑owner.
4. **Methodology‑Performance view** with the statistical discipline baked in (design §7): **pooled across clients** (per‑client A/B is hopeless, \~107 posts/arm); "Not enough data yet" under min‑n (\~80–100/arm); never a point estimate without a CI; **causal language only from the randomized arm** with CI excluding 0; observational pre/post labeled "directional, not controlled"; per‑creator data descriptive‑only.

## Confounder control (decided)

**Randomization, not topic‑clustering.** Per‑piece flag assignment balances client/virality/timing/topic by construction; absorb residual variance with `outcome ~ arm + (1|clientId) + (1|topicCluster)`. Topic is recorded in the fingerprint, never used as an analytical control. Topic‑cluster matching is cut (false precision at our n).

## Out of scope

Slow‑rung outcome crons, ICP pipeline, booked‑calls, the optimizer (→ Slice 3). The frozen judge guardrail stays a Convex/CI constant (MAE‑219), never PostHog.
