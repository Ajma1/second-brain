# Build and roll out the legacy Blueprint migration bridge

- **Identifier:** MAE-475
- **Status:** Done
- **Assignee:** Tim Keen
- **Team:** MAE
- **Updated:** 2026-07-12
- **URL:** https://linear.app/modern-agency-sales/issue/MAE-475/build-and-roll-out-the-legacy-blueprint-migration-bridge

## Scope

Extend the existing [MAE-462](https://linear.app/modern-agency-sales/issue/MAE-462/alpha-onboarding-cli-and-posts-rename-execution-stack) onboarding CLI/import path to ingest the legacy Supabase Blueprint cohort without importing the legacy product.

### Source and package contract

* Inventory legacy prospects/posts and emit a redacted aggregate report before export.
* Normalize each eligible prospect into the existing onboarding manifest/package model.
* Carry profile/ICP/voice/knowledge context, recommended headline/about text, three lead-magnet ideas, and all draft posts.
* Preserve stable legacy prospect/post IDs, content hashes, template/order/readiness, `to_fix`, and action-item metadata.
* Quarantine malformed identity fields and explicitly report exclusions.

### Maestro import hardening

* Replace body-text dedupe with tenant-scoped stable source receipts.
* Link every imported draft to the imported client persona.
* Record provenance and import status so retries are idempotent and reconcilable.
* Run import-quality checks and project missing requirements.
* Preserve drafts without making them approvable or schedulable by default.

### Activation

* Stage packages for the full eligible cohort.
* Pre-materialize only an approved managed-sales cohort.
* Create no fake users; issue a verified invitation/claim and attach on first authenticated login.
* Keep MAS as owner for managed workspaces and grant the customer admin access.
* Enforce bounded/resumable batches and receipt-based rollback.

### Safety and proof

* Rotate exposed Convex deploy keys and use BWS-backed deployment credentials.
* Use synthetic records in dev/staging; real customer data requires an explicitly approved production canary.
* Prove incomplete imported drafts cannot be approved or scheduled through CMO.
* Run focused tests, required full gates, staging dry-run/apply/replay/rollback, production canary, and cohort reconciliation.

## Scope Guard

This issue may change onboarding package/CLI code, generic import receipts, draft/persona/source-context importers, invitation/claim activation, CMO imported-draft readiness, focused UI needed to finish missing context, tests, and launch runbooks. It must not recreate Blueprint pages, broaden unrelated workflow-native onboarding work, or modify publishing semantics beyond the imported-draft safety gate.

## Quality Targets

* Exact-once logical import under retries.
* Fail-closed tenant and identity attachment.
* Zero implicit publishing side effects.
* Every source row ends in imported, skipped-with-reason, or quarantined.
* Rollback is receipt-driven and cannot remove customer-authored changes.

## Test Plan

* Source normalizer: valid, partial, malformed identity, duplicate, and retry fixtures.
* Import states: loading/dry-run, empty, ready/read, ready/edit, mutation success/failure.
* Activation: wrong email, expired/revoked claim, existing membership, retry, and cross-tenant denial.
* CMO: incomplete block, repaired readiness, approve attempt, schedule attempt, and stale-source invalidation.
* Operations: dry-run/apply/replay/reconcile/rollback with synthetic canaries.

## Done when

Implementation is merged, current main is deployed to canonical staging, synthetic canaries and rollback pass, exposed keys are rotated, a production target and approved real canary are pinned, the canary is reconciled, and the full cohort rollout produces a signed-off aggregate reconciliation report.
