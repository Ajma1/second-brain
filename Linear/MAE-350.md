# Source-fidelity gate — block/flag draft content not traceable to source transcript

- **Identifier:** MAE-350
- **Status:** Backlog
- **Assignee:** —
- **Team:** MAE
- **Updated:** 2026-06-20
- **URL:** https://linear.app/modern-agency-sales/issue/MAE-350/source-fidelity-gate-blockflag-draft-content-not-traceable-to-source

## User Story

**As a LinkedIn ghostwriter, I want the AI to use only the speaker's exact words, phrases, and ideas from the transcript — never inventing or "putting a twist" on what was said — so that my client's authentic voice and actual positions are preserved.**

## Source

Dalton Danks call (2026-06-18). Dalton's #1 pain point: Claude puts a twist on what the speaker actually said, invents phrases. He spends significant time per post manually cross-referencing drafts against transcripts to catch this.

> "did he actually say that in the script in the original recording or is that did you kind of like put a twist on that? It's usually my intuition just kind of an alarm goes off"

## Gap from Existing Issues

[MAE-290](https://linear.app/modern-agency-sales/issue/MAE-290/e1-10-review-transparency-claims-sources-and-golden-nugget-insight-on) (review transparency) shows grounding/sources on each draft. [MAE-264](https://linear.app/modern-agency-sales/issue/MAE-264/e5-3-agent-context-pack-cited-role-scoped-always-current) (agent context pack) ensures generation uses cited context. Neither enforces a **generation-time constraint** that blocks or flags content not traceable to source material. This is about a hard gate, not transparency.

## Prior Art (reference for concepts, not code to port)

**maestro-v2-3** (fully built, 3 layers — likely overbuilt):

* `lib/brainScore.ts` — `validateGrounding()` does verbatim-substring checking, >30% failure threshold pauses run
* `brain/claims.ts` — `CLIENT_CLAIM_REQUIRES_CITATION` enforcement, `claimCitations` table
* `lib/outputGate.ts` — two-part gate: deterministic banned-phrase screening + Haiku voice-match judge
* ADR-003 provenance honesty (LOCKED)

**mas-platform**:

* `trigger/process-transcript-provenance.ts` — derives source citations with `source_offset_ms`, `source_turn_index`, `source_quote` by fuzzy-matching
* `server/services/magnet-from-transcript.service.ts` — minimum grounding gate (>=3 knowledge entries or refuse)
* `lib/ai/magnet-generation/types.ts` — carries `source_entry_ids` through every generation stage

**maestro-agent-planning**: ADR-003 spec defines provenance as locked architectural decision.

## Implementation Notes

Build clean. The v2-3 implementation has 3 separate layers that could be consolidated. Core concept: every claim in a draft must trace to a source chunk, and a post-generation verification pass flags anything that can't be traced. Consider a simple pass that diffs draft claims against source transcript before presenting to the ghostwriter.
