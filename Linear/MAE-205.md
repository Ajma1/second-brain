# [ARCH-016] Add Convex coding standards and deterministic static gates

- **Identifier:** MAE-205
- **Status:** In Progress
- **Assignee:** Tim Keen
- **Team:** MAE
- **Updated:** 2026-06-15
- **URL:** https://linear.app/modern-agency-sales/issue/MAE-205/arch-016-add-convex-coding-standards-and-deterministic-static-gates

## Context

The agent swarm should not be trusted to write correct Temporal code from memory. We need strict coding standards and deterministic gates that fail illegal patterns before review. This issue turns the Maestro Temporal doctrine into enforceable checks.

Parent context: [MAE-201](https://linear.app/modern-agency-sales/issue/MAE-201/arch-012-add-temporal-factory-review-gates-and-evidence-policy).

## Scope

Define and prototype deterministic gates for Temporal workflow packages:

* forbidden imports in workflow files: DB clients, HTTP clients, model providers, filesystem, event-stream writers, `crypto.randomUUID`, DOM/Node APIs
* workflow files may import Temporal workflow APIs, shared pure types, pure state-machine/gate helpers only
* Activities require timeout and retry policy at call sites
* workflow args/returns must be typed serializable objects
* workflow IDs must be business-meaningful helpers, not random ids
* task queue names must come from a documented registry
* export/sync/publish command handlers must validate object version readiness
* replay/determinism test is required for any workflow package

## Acceptance Criteria

* Coding Standards get a strict Temporal section with allowed/forbidden patterns.
* Factory has a deterministic lint/check plan for Temporal workflow packages.
* The gate suite includes positive and negative fixtures for each blocked pattern.
* CI/factory output reports file path, rule id, location, severity, and fix guidance.
* Checks are deterministic and do not require model calls.
* Gate results can be persisted as Fabro evidence.
