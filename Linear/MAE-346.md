# [E1-7.3] Gate streaming — live status rail subscribing to gateRuns

- **Identifier:** MAE-346
- **Status:** In Review
- **Assignee:** —
- **Team:** MAE
- **Updated:** 2026-06-18

PR-3 of MAE-245 [E1-7] Gate streaming. Stacks on PR #220 (`feat/gate-streaming-workflow-MAE-340`).

## Scope

Client-side reactive surface that renders live gate-run status during a batch generation. ~280 LOC.

* `apps/web/components/cockpit/GateRunsRail.tsx` — NEW client component. `useQuery(api.capabilities.gateRuns.listGateRunsForBatch, { batchId })`. Renders each run row with phase + status + animated streaming text while `status: "running"`.
* `apps/web/components/cockpit/GateRunRow.tsx` — NEW. Per-row: phase label, status badge, elapsed timer.
* Wire into the cockpit batch surface where it makes sense.

## Out of scope

Persistent-text-streaming via real WebSockets — the Convex `useQuery` reactive subscription IS already the streaming primitive; sub-second updates suffice.

## Constraints

* Notion-kit primitives only; no raw `button/input/select/textarea/dialog`.
* Phase labels via closed token-map object (NOT a switch).
* `Intl.DateTimeFormat(undefined, …)` — never hardcoded locale.
* No `Date.now()` in render — pass through props.
* ≤300 LOC. No suppressions.
