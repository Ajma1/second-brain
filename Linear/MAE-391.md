# Product Brain consolidation map — one canonical Brain

- **Identifier:** MAE-391
- **Status:** In Review
- **Assignee:** Tim Keen
- **Team:** MAE
- **Updated:** 2026-06-22
- **URL:** https://linear.app/modern-agency-sales/issue/MAE-391/product-brain-consolidation-map-one-canonical-brain

## User Story

As a Maestro operator, I want one explicit Product Brain ownership map, so contributors stop treating `conceptVersions`, OKF, the native corpus bridge, and `maestro-score` as competing Brain implementations.

## Context

[MAE-264](https://linear.app/modern-agency-sales/issue/MAE-264/e5-3-agent-context-pack-cited-role-scoped-always-current) established the Brain v1 read/lifecycle API surface and [MAE-367](https://linear.app/modern-agency-sales/issue/MAE-367/product-brain-native-corpus-artifact-and-read-bridge-cutover)/[MAE-368](https://linear.app/modern-agency-sales/issue/MAE-368/product-brain-native-corpus-artifact-and-read-bridge-cutover) added native versioning and bridge validation. The remaining confusion is product/process clarity: there is one canonical cited client-truth store in Convex, while OKF/concepts and native corpus are compatibility/projection/bridge surfaces.

## Scope

* Add `docs/product/brain/consolidation-map.md`.
* Declare the canonical store: `sources`, `sourceChunks`, `claims`, `claimCitations`, `knowledgeFiles`, `extractionRuns`, `contextPackRuns`, plus Brain-specific append-only version ledgers.
* Declare non-canonical surfaces: `conceptVersions`/OKF compatibility, legacy concept context packs, native corpus bridge artifacts, and `maestro-score` fallback.
* Map deferred product work to existing or new Linear slices without duplicating positions/health/ingestion issues.
* Add a README link so future Brain work starts from the same boundary.

## Acceptance

* Docs state that new cited claim/source truth must not be added to `conceptVersions` or native corpus artifacts.
* Docs state OKF remains wanted as a portability/export projection, not as canonical storage.
* Docs identify existing slices for positions/readiness and health, plus follow-up slices for OKF projection, native corpus import, and supervised ingestion.
* No runtime behavior is changed.
