# [EPIC] Agency Client Content Pipeline Foundation

- **Identifier:** MAE-308
- **Status:** Backlog
- **Assignee:** —
- **Team:** MAE
- **Updated:** 2026-06-17
- **URL:** https://linear.app/modern-agency-sales/issue/MAE-308/epic-agency-client-content-pipeline-foundation

## Why

Create the missing cross-cutting foundation for Maestro's first functional agency workflow:

`client persona onboarding -> Harvest intake -> idea bank -> select 7 ideas -> draft 7 LinkedIn text posts -> agency approval -> ready/scheduled`

This epic should track foundation work that is not already covered by the existing E1-E10 product story issues. It should create reusable capabilities, workflows, schemas, adapters, and parity surfaces that UI, CLI, admin, and future agents can all call.

## Approved decisions

* Agency workspace owns many client personas.
* Client persona is not an auth user.
* v1 assumes one authenticated agency operator; multi-seat agency roles are later.
* Use Maestro-admin-owned Harvest API key in Convex env.
* Normal Harvest API-key mode only; no custom LinkedIn cookies, proxies, account sessions, or agency-supplied Harvest credentials.
* Onboarding requires client name + LinkedIn profile URL. Website, offer, audience/ICP, goals, cadence, notes/files are optional and encouraged.
* Initial Harvest pull covers one year of LinkedIn profile, posts, and comments/replies.
* Harvest intake runs in the background after client creation.
* Wait until initial Harvest intake finishes before automatic idea generation.
* Generate 20-30 sourced post ideas.
* Agency selects 7 ideas; Maestro drafts 7 LinkedIn text-only posts immediately.
* Agency edits until approved. Approved means ready to post.
* Schedule date/time is optional. Actual publishing is future work.
* CLI and UI expose every action through the same backend surface.
* Admin is a v1 superadmin monitor/read surface across agencies, clients, onboarding, Harvest, ideas, drafts, approvals, schedules, and errors.

## Architecture notes

Follow `AGENTS.md` and `docs/architecture.md`:

* Capabilities are the smallest useful verbs.
* Workflows compose capabilities in known sequences.
* Policy is data; agency methodology is split into policy areas.
* Harvest access lives behind an adapter.
* Market intelligence is a Maestro-owned data product stored in Convex and read through small capabilities.
* UI, CLI, admin, MCP, and agents are all clients of the same capability/workflow surface.

## Non-goals

* No actual LinkedIn publishing in this slice.
* No custom Harvest cookies/proxies/session handling.
* No client-facing approval link.
* No multi-seat agency role system.
* No external/reference account ingestion list in v1.
* No carousel/visual content drafting in v1.

## Done when

* Child issues define the missing capability, workflow, schema, UI, CLI, admin, test, and decision work.
* Existing E1-E10 issues are not duplicated.
* Each child issue is small enough to become a focused plan/PR stack later.
