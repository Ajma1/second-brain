# [E1-2] Preserve free editor product surface intent from superseded PR #111

- **Identifier:** MAE-334
- **Status:** Backlog
- **Assignee:** —
- **Team:** MAE
- **Updated:** 2026-06-17
- **URL:** https://linear.app/modern-agency-sales/issue/MAE-334/e1-2-preserve-free-editor-product-surface-intent-from-superseded-pr

## Why

PR #111 was the first broad attempt at the free co-edit product surface: a visible editor route, BlockNote editing shell, annotation rail, empty-document seeding, and accept/reject UX. We are not merging PR #111 because the narrower green stack (#131, #147, #163) has the better backend architecture and review posture, but we should not lose the product intent.

## Decision

Treat PR #111 as product-design reference only, not an implementation branch to merge.

Merge path for the foundation:

1. PR #131 — deps + singleton ProsemirrorSync adapter + BlockNote schema seam.
2. PR #147 — schema tables and BlockNote JSON parser.
3. PR #163 — prosemirrorSync re-export, draftVersions seed/snapshot path.

After those land, rebuild the free editor surface on top of the new stack and existing child work (#327 route shell, #330 editor surface, #332 auth/selection bridge).

## Preserve from PR #111

* Actual editor route/surface intent: `/editor/[pieceId]` style product entry.
* BlockNote editor shell and loading/empty document states.
* `useBlockNoteSync` integration pattern, adapted to the new `prosemirrorSync` API shape.
* Right-side annotation/suggestion rail UX.
* Accept/reject controls and product flow.
* Product expectation that opening a piece gives a usable free editor, not just backend plumbing.

## Do not carry forward from PR #111 as-is

* `documentSync` / `documentRead` / `documentWrite` backend shape.
* Text-anchor annotation schema (`open/resolved/accepted/rejected`) in place of the tracked-markup schema from PR #147.
* Prompt-defense/meta-gate changes bundled into PR #111.
* Any merge-conflict resolution that forces PR #111's adapter/schema model over the green stack.

## Acceptance criteria

* PR #111 can be closed as superseded without losing the product-surface requirements.
* The rebuilt editor surface uses the schema/sync model from #131/#147/#163.
* The route opens an existing piece, seeds an empty BlockNote document when needed, and persists snapshots through the approved sync path.
* Suggestion rail reads from the tracked-markup annotation model anchored to `draftVersionId` / block position / before-after BlockNote JSON.
* Accept/reject paths are wired only through capability/workflow APIs that enforce workspace tenancy.
* Verification includes `pnpm verify`, a product smoke test, and unauthorized/cross-workspace access checks.
