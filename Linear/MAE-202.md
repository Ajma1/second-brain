# [ARCH-013] Validate Convex deploy, Agent Mode, and packaging path

## Context

Before Temporal becomes the Maestro V2 product runtime, we need to prove workers can be packaged and deployed repeatably, not just run in local test mode.

Planning doc: `docs/operator/plans/active/2026-05-21-temporal-factory-daytona-integration.md`

## Scope

Validate the production packaging path for TypeScript Temporal workers.

Areas to cover:

* glibc-based Node worker image, not Alpine/musl
* required TLS certificates in slim images
* ahead-of-time workflow bundle generation
* task queue registration expectations
* worker start/connect/poll/drain/shutdown lifecycle
* OpenTelemetry/metrics configuration
* final decision on initial Temporal Service target: local dev, self-hosted, or Temporal Cloud for production-like environments

## Acceptance Criteria

* A minimal production-style worker image builds from a clean checkout.
* The worker image starts, connects to Temporal, polls the intended task queue, runs a smoke workflow, drains, and shuts down cleanly.
* Worker code is pre-bundled or the decision not to pre-bundle is explicitly justified with startup evidence.
* The packaging smoke emits logs and metrics suitable for factory evidence.
* The deployment path documents required env vars, task queue naming, namespace strategy, and connection/security settings.
* The result informs whether the first production-like runtime target is Temporal Cloud or self-hosted Temporal.
